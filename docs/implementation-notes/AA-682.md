Linear AA-682 (operations MVP; S5 = My Payments, customer side). Sources: root S252 design

## Decisions

- **One BFF route, one upstream call**: `GET /api/me/payments` → Booking `GET /booking/customer/v1/payments`, which
  returns every visible request in full (schedule, verified payments, instructions). No per-invoice call.
- **The traveller's token is the only credential to Booking** (Booking verifies EXTERNAL x {tripplanner,
  booking-customer}); the TripPlanner API key never leaves for Booking.
- **Booking 401 does not clear the session cookies** (unlike `/api/me`, where the Lambda's 401 does): the trips list is
  the session's judge; a Booking misconfiguration (client id, issuer) must not sign travellers out. The section shows
  "Sign in again to see your payments".
- **Allow-list in the BFF** (`pickPayments`): only the contract's fields reach the browser, even if Booking ever sent
  more (defence in depth on top of Booking's response models and the root contract checker).
- **Placement**: a "Payments" section below My Trips, one card per request; the card takes the planned trip's title
  when `planner_trip_id` matches a trip in the list, else "Your trip" + the booking reference. Showing it inside each
  trip card would hide requests whose trip was created by staff or is not in this account's list.
- **Default Booking URL in code** (`https://api-booking.lumiguides.it.com`, public host) with env `BOOKING_API_URL` as
  an override, so no Vercel env change is needed for Dev (all TripPlanner environments call Dev today).
- **Overdue chip = new `danger` tone of `ui/Badge.tsx`** (red on red-soft, already in the contrast guard's pairs),
  built once in the kit, not a page-level class.
- Amounts are shown from the API's decimal strings with `Intl.NumberFormat` (the currency's own decimals: VND without
  decimals); nothing is computed on the client.

## Changed (vs. the design)

- Status labels: To pay (sent), Partly paid, Paid in full, Cancelled. Schedule kinds: Deposit, Second payment, Final
  payment, Payment.
- "How to pay" adds "Please quote INV-… with your payment. It shows here once our team has checked it." (payments are
  verified by hand before they appear).

## Tradeoffs

- No Playwright suite in this repo (CONTEXT: header smoke only); evidence = unit tests of the pure half + screenshots
  of `/trips` with the two API answers mocked in the browser (1440 / 390, light / dark, empty, signed-out).
