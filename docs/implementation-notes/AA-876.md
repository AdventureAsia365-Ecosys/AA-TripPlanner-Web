# AA-876 — API edge hardening (TripPlanner part)

Scope here: security headers on the frontend and a production header check. Login throttle, CORS and the API
Gateway throttle are in AA-CIS-App / AA-CIS-Infra; the Booking docs gate in AA-Booking.

## Decisions

- **Same six headers as the CIS portal (AA-885)** in `frontend/next.config.mjs` `headers()` on `/(.*)`, plus
  `poweredByHeader: false`. Minimal CSP (framing, `base-uri`, `form-action`, `object-src`) — no `script-src`, so
  Next inline scripts, Mapbox GL and the inline styles keep working.
- **HSTS `includeSubDomains`, no `preload`.** The production host is `aa-tripplanner.vercel.app` (not an apex we
  own), so `includeSubDomains` only covers its own (non-existent) sub-domains. Vercel already sends its own HSTS
  (with `preload`) on `*.vercel.app`; the check accepts either.
- **`Permissions-Policy` turns geolocation off**: no code uses the browser Geolocation API (grep), the map is
  driven by the trip, not the device position. Turn it on here first if a "near me" feature arrives.
- **Header smoke in `vercel-deploy.yml`.** TripPlanner has no UI smoke workflow, so the production deploy job
  gets a step that fetches `https://aa-tripplanner.vercel.app/` (public; the deployment URL itself sits behind
  Vercel protection) and fails red if any of the six headers is missing (3 tries, 10 s apart). The script was
  dry-run locally: it fails on today's production (no headers) and passes against the portal host.

## Changed

- `frontend/next.config.mjs`, `.github/workflows/vercel-deploy.yml` (new step "Check the production security
  headers", production target only), `CONTEXT.md` (Frontend section).

## Tradeoffs

- `frame-ancestors 'none'` + `X-Frame-Options: DENY` block any partner iframe of TripPlanner (B2B embeds, KAN-20)
  until an allow-list is designed.
- The new step checks the production alias, which `vercel deploy --prod` has just pointed at this deployment; if a
  second production deploy raced it, the check still reads a deployment built from a commit with the headers.

## Should know

- This is a CI workflow change: it must run once for real (lesson "Workflow CI phải chạy thật một lần") — the
  first production deploy after merge is that run (the PR's preview deploy does not run the step).
- Also run `docs/smoke-test-runbook.md` after the production deploy.
- No env var, no secret.
