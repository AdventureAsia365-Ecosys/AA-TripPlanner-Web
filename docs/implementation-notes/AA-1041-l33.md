# AA-1041 — planning chat fixes after the S277 live smoke (lane S277 l33)

The live smoke of the planning chat on Dev (root `docs/audits/2026-11-11-S277-tp-chat-smoke/README.md`, after PR #252)
found four problems. This lane fixes them in one TripPlanner PR, no migration. Main notes of the chat:
`AA-1041.md` section "Slice 2".

## Decisions

- **A route ask ends with a plan: prompt rule + server fallback.** Rule 3 of `_SYSTEM` now says: when the traveller
  names a country AA sells and a number of days, call `route_options`, propose the best-fitting option as a `replace`
  and mention the others in one sentence; do not ask to choose first. The model can still ignore it (the smoke turn
  "4 days in Laos" listed three routes and asked which one), so the server backs it up: when the turn's **last** tool
  was `route_options` with at least one option and the model answered (`kind: answer`) with **no** proposal at all,
  the server builds a `replace` proposal of the first option's pinned days (`first_route_proposal`, through
  `build_proposal`, so only catalog references of this turn) and appends one server sentence to the model's reply
  (`SERVER_PROPOSAL_NOTE`: "I have put the first option below as a plan you can apply ..."). Not when the model's
  proposal was dropped (it named something outside the catalog: nothing of its plan is trusted), not on a refusal,
  not when a later tool (find_experiences, ...) answered after `route_options`. The ledger signal carries
  `server_proposal: true`, so the rate at which the prompt rule fails can be read from `quality_signal`.
- **Why both.** The prompt rule alone is not testable and not reliable on the fallback model (Sonnet 4.6 while 5.5 is
  refused on acc3); the server fallback alone would leave the model's question "which one?" above a plan without
  explanation. With the rule the model usually proposes itself; the fallback covers the rest and says what it did.
- **Grounding: which words tripped it.** The ledger has counts, not text. Of the 10 answered calls of the smoke, the
  6 rows with `ungrounded` were 4 turns: the off-catalog ask ("Peru") and the injection ("Palace of Zorbu"), both
  correct, and the two browser turns "Plan 3 days in Laos", whose replies were replaced although the proposal was
  valid. The same turn through the API (turn d) passed with "Blue Lagoons", "Buffalo Dairy", "Vang Vieng". The
  shapes that fail a reply like that: "Day 2" mid-sentence (the prompt shows the trip as "s1 Day 1: ..."), "3-Day"
  (the old word regex read "Day" after the hyphen as a mid-sentence capital), a singular "Lagoon" for the catalog's
  "Lagoons 1", "Northern", a demonym ("Lao"), contractions ("I've", "Don't") and sentence starters outside the short
  list ("Swim", "Afterwards", "Starting").
- **Grounding: the fix is normalisation + ordinary words, never the traveller's words.**
  - Words are compared by `_key`: lower case, possessive / contraction dropped, plural "s" dropped (not "ss", not
    words of 3 letters): "Lagoons" = "Lagoon", "Laos" = "Lao".
  - The grounding scan splits on hyphens (`_NAME_RE`): "3-Day" is "Day", "Zorbu-style" is "Zorbu".
  - `_ALWAYS_OK_WORDS`: ordinary English words a reply capitalises inside a name or a title (day, option, route,
    river, temple, market, lagoon, falls, island, northern, central, unesco, ...). A lower-case word is never checked,
    so the same word in capitals adds no risk; the distinctive word of an invented name stays in no list. Travel
    services AA does not sell (hotel, resort, airline, airways, flight, airport) are left out on purpose.
  - `_SENTENCE_STARTER_WORDS` is wider (verbs and adverbs a reply opens with, contractions).
  - `DEMONYMS`: demonyms of countries AA sells, added to the turn's vocabulary only for the countries on the offered
    list (a sold country's "Lao", "Khmer", "Vietnamese"; a demonym of a country not sold still trips the rule).
  - Still flagged (tests): "Palace of Zorbu" -> Zorbu, "Zorbu awaits you" -> Zorbu, "Grand Harbour Hotel" ->
    Harbour + Hotel, "Skyline Airways", "Kyoto", "Peru", a demonym of a country not sold.
- **The AI label sits under each AI-written reply, not in the header.** `showsAiLabel` (lib/planChat.ts): an
  assistant reply with `ai_generated: true`; server sentences and the panel's notices get none. The kit `AiNotice`
  (variant narration, "Use of AI" link) renders under the bubble. The intro card (before the first message) now says
  the suggestions come from "the planner's AI assistant", so the traveller is told before the first AI reply.
- **Refusals name every country AA sells, by name.** `fallback_reply` sorts the offered countries (live tours only,
  `chat_tools.COUNTRIES_SQL`) case-insensitively and names them all; `FALLBACK_COUNTRIES` (top 8 by tour count) is
  gone. 21 countries today; the reply bubble wraps.

## Tradeoffs

- A wider ordinary-word list lets a name made only of ordinary words pass ("the Old Town Walk" when the catalog has
  none). The same words in lower case always passed, and the proposal is still built from catalog references only;
  the check exists to catch invented proper names, which still trip it.
- The server proposal picks the first option (`routes.proposals` order), not the one the model would call "best".
  The appended sentence says so and invites the traveller to ask for another.
- One AI notice per AI-written reply is longer than one header line in a long conversation; it is accurate per line,
  which the header was not.
