# AA-904 — Next.js 14 → 15 upgrade (replaces Dependabot PR #104)

Branch `chore/aa-904-next15`. Frontend only (`frontend/`), no backend, migration or env change.

Final versions: `next` 15.5.28 (latest 15.x, npm dist-tag `backport`), `react` / `react-dom` 19.2.4,
`eslint` 9.39.5, `eslint-config-next` 15.5.28, `@eslint/eslintrc` 3.3.7 (new), `postcss` 8.5.31,
`@types/react` 19.2.18, `@types/react-dom` 19.2.7. Unchanged: `mapbox-gl` 3.7.0, `tailwindcss`
3.4.14, `typescript` 5.6.3, `@types/node`.

## Decisions

- **Next 15, not 16.** The issue allows either. A trial of Next 16.4.2 on top of this branch (scratch
  copy, not committed) builds and type-checks unchanged, and `npm audit --omit=dev` is clean, but
  `eslint-config-next` 16 brings the React Compiler rules (`eslint-plugin-react-hooks` 7) and reports
  **23 errors**: `react-hooks/refs` 14, `react-hooks/set-state-in-effect` 8, `react-hooks/immutability`
  1, in `lib/useTrip.tsx` (13), `components/MapView.tsx` (5), `TripPanel.tsx` (2),
  `DestinationPopup.tsx`, `GuestResetNotice.tsx`, `TourListPane.tsx`. Fixing them means refactoring
  the planner's trip-state hook (refs read during render), which is the riskiest code in the app and
  needs a real smoke of map / search / plan / send-to-advisor. So 16 is not "the same effort": it is
  this PR plus a planner-hook refactor. Recommended as a follow-up issue (see Should know).
- **React 19 for the App Router.** Next 15 accepts React 18 as a peer, but the App Router needs 19.
  Pinned 19.2.4, the version CIS admin, CIS portal and Booking use.
- **ESLint 9 + flat config via `FlatCompat`.** `eslint-config-next` 15 still ships eslintrc presets, so
  `eslint.config.mjs` loads `next/core-web-vitals` through `@eslint/eslintrc` (the Next 15 docs
  pattern). Same rule set as before; `next/typescript` was not added (it would add new rules unrelated
  to the upgrade). `eslint-config-next` 15 caps its peer at ESLint 9; npm marks 9.x deprecated
  (ESLint 10 is current), a dev-only tool, gone with the Next 16 move.
- **`npm run lint` = `eslint .`** instead of `next lint` (deprecated in 15.5, removed in 16), matching
  CIS and Booking. `next build` still lints with the same flat config.
- **Route segment config as a literal.** `export const revalidate = CATALOG_REVALIDATE_S` (imported)
  fails the Next 15 build ("Unknown identifier ... at revalidate", segment config is read
  statically). The home, tour and destination pages now say `1800`; a new unit test
  (`lib/segmentConfig.test.ts`) fails if a literal drifts from `CATALOG_REVALIDATE_S`.
- **`next-env.d.ts` no longer committed.** Next 15.5 rewrites it on every build/dev with a reference to
  `.next/types/routes.d.ts`; committing that line would break the CI type-check (it runs before the
  build, `.next` absent). Ignored like CIS and Booking; `tsc --noEmit` passes without it (checked
  with `.next` and `next-env.d.ts` removed).
- **`overrides: { next: { postcss: "$postcss" } }`.** Every Next 15 release pins postcss 8.4.31, which
  carries high advisories (sourceMappingURL file read, `</style>` XSS in stringify); only Next ≥ 16.3
  moves to 8.5.x. The override makes Next use the top-level postcss 8.5.31. The built CSS is
  byte-identical with and without it (md5 of both `.next/static/css/*.css` files compared). Remove
  the override when moving to Next 16.

## Tradeoffs

- **Fetch / route-handler caching defaults (Next 15: `fetch` and `GET` handlers uncached by default).**
  Checked rather than assumed: the same mock-upstream smoke on Next 14 (main) and Next 15 (branch)
  gives 2 upstream hits for 2 calls of `/api/browse?resource=countries` and of `/api/trip?trip_id=…`
  on both, so the BFF was already uncached on 14 and nothing changes. Catalog reads keep their explicit
  `next: { revalidate: 1800 }`, so ISR is unchanged.
- **Page cache header.** ISR pages now send `s-maxage=1800, stale-while-revalidate=31534200` (Next 15
  default `expireTime` 1 year) instead of `s-maxage=1800, stale-while-revalidate`. Same freshness
  window (30 min); the explicit SWR bound is the Next 15 default and Vercel serves ISR itself.
- **First Load JS** shared by all pages 87 kB → 103 kB (React 19 + Next 15 runtime); `/plan`
  494 kB → 504 kB. Accepted as the cost of the supported major.
- Remaining `npm audit` findings are **dev/build-time only** (none in `--omit=dev`): the
  `tailwindcss` 3 chain (`chokidar` / `micromatch` / `braces`, `postcss-nested` /
  `postcss-selector-parser`, fix = Tailwind 4) and `eslint-config-next` 15 (`fast-glob` →
  `micromatch` → `braces`, fix = `eslint-config-next` 16). Out of scope here.
