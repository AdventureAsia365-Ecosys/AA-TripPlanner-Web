# AA-812 — Search-first home, tour pages (PDP), destination pages (S236)

Lane tp-812, branch `feat/aa-812-search-home-tour-pages`, stacked on `fix/aa-805-ai-phase0-leg-order`
(PR #71: it touches `Header` / `TripPanel`). Written while implementing.

## Decisions

- **New reads go only through the CIS catalog views** (ADR 0001, CIS migration 225, contract
  `catalog.tour.v1`): `catalog.v_tour`, `v_tour_day`, `v_tour_place`, `v_tour_photo`,
  `v_destination`, `v_destination_photo`. No new code reads `gold_aa_internal` / `silver_*`.
- **New browse resources live under `/browse/catalog/*`** so the existing API Gateway route
  `ANY /browse/{proxy+}` already covers them (no Infra change).
- **Backend resources (browse Lambda, `backend/browse/catalog.py`)**:
  `GET /browse/catalog/tours` (filters `country` name-or-slug, `min_days`/`max_days`, `month`,
  `sort` = featured | duration_asc | duration_desc | recent | title, `limit` ≤ 60, `offset`),
  `GET /browse/catalog/tours/{slug}` (catalog.tour v1 + display helpers),
  `GET /browse/catalog/destinations` (countries with live tours),
  `GET /browse/catalog/destinations/{country-slug}` (stats, top tours, places with lat/lng, photos),
  `GET /browse/catalog/sitemap`; plus `GET /browse/tour-route?tour_id=` for "Customise this trip".
  All 200s use the existing CDN TTL header; 400/404 are `no-store`.
- **Travel month is derived in Python** from the free-text `best_time_to_go`
  (`months_from_text`: "October to April", "Nov - Mar", lists, "all year"; ranges wrap the year).
  A tour whose text names no month is *kept* by a month filter (unknown ≠ wrong season).
- **Retired tours** (`lifecycle_stage = 'retired'`; the catalog does not filter it) are hidden
  from lists, the home, destination pages and the sitemap, but their page still answers so old
  links keep working.
- **Slug drift**: `catalog.v_tour.slug` changes with the title. The tour read matches the slug,
  else the 8-hex source-id suffix of the slug, and returns the current slug; the page redirects.
- **"Featured" instead of "Popular"**: the catalog has no sales/traffic signal, so the home
  section is "Featured tours" = tours with photos first, then newest. No popularity claim.
- **Photo URLs are absolute in responses** (`CIS_PUBLIC_API_BASE`, default the Dev CIS API), so
  the frontend never needs the CIS base.
- **"Customise this trip" uses the existing apply-route flow**: `tour-route` builds the tour's
  first-to-last-stop proposal from the planner's own `tripplanner.tour_stop` /
  `itinerary_components` (same shape as `/browse/routes`), titled from `catalog.v_tour`.
  404 when the tour is not in the Tour Graph yet → the planner falls back to country + days.
- **Fixtures only under `backend/tests/`** (`catalog_fixture.py`, `dev_browse_server.py`); that
  directory is dropped from the Lambda zip. The fake pool answers the module's exact SQL
  constants, so the same fixtures drive the unit tests and local screenshots.
- **Design system = copy, not import** (Nghiệp S236): `frontend/ui/tokens.css` holds the CIS kit's
  core `--aa-*` palette with identical light/dark values, plus brand type (Fahkwang + Poppins via
  next/font). Tailwind exposes them as `k-*` colours. Core components: `Button`/`ButtonLink`,
  `Badge`, `Photo`, `EmptyState`/`ErrorState`, `Icon`, `ThemeToggle`. Theme model = CIS (choice in
  localStorage `tp_theme`, resolved to `<html data-theme>` by a pre-paint script).
- **Planner stays light-only**: its components use the hex `aa-*` Tailwind palette and Inter;
  switching them to the theme tokens would change every planner screen, out of scope here.
- **/plan pre-fill never mutates on its own except for an empty trip**: `?tour=` on an empty trip
  pins the route at once; on a trip with stops a banner asks first (apply-route merges, never
  deletes). Waits for the saved-trip restore (`ready`) so it cannot race it.
- **Travellers** are carried in the planner intent and shown in the route finder; they are not
  sent anywhere (no field in `inquiry.submitted` v1.1).
- **Tour/destination pages render on demand (ISR)**: `generateStaticParams` returns `[]`, nothing
  hits the browse Lambda at build. The home is prerendered at build and revalidated every 30 min.
- **Static Mapbox images** (not Mapbox GL) on tour/destination pages: zero map JS there; no
  token → no map, the numbered place list carries the information.
- **No "from" price anywhere** (no price source until AA-Booking/ADR 0005).

- **Review fix — /plan is pinned to light** (review blocker 1): the theme restore script returns
  `light` on `/plan`, and `PlannerApp` pins `data-theme="light"` while mounted (client-side
  navigation from a dark kit page) and gives the stored choice back on leave (`pinLightTheme`).
  The stored choice is never changed. Chosen over scoping `color-scheme` to `.aa-site`, because
  the planner also has a few token-styled bits and must not mix themes.
- **Review fix — home search numbers** (major 2): days/travellers keep the raw string while
  typing and clamp on blur/submit (`clampCount`), so "14" stays 14.
- **Review fix — destination places query** (major 4, partial): `COUNTRY_PLACES_SQL` now takes the
  listed tours' ids (`tour_id = ANY($1::uuid[])`) instead of joining `v_tour` on the computed
  country slug, so the uuid predicate can be pushed into the security_barrier view.
- **Month parsing**: "may" counts only when written "May"; clauses starting with avoid / not /
  except / excluding remove their months ("All year except July", "avoid June to August").
- **Stable "Customise" links**: the tour page sends `source=<source_id>` next to `tour=<tour_id>`;
  `/browse/tour-route` resolves the current `tour_id` from `source_id`
  (`catalog.v_tour.source_id`, a plain column), falling back to the `tour_id` passed.
- **Legacy itinerary**: the tour answer carries the contract's `itinerary_text`; the page shows it
  as written when `days` is empty, instead of "being prepared".

## Changed

- `/` was the map planner; it is now the search-first home. The planner moved to `/plan`
  (`app/plan/PlannerApp.tsx`, same code) with a Map | List-of-tours toggle and the pre-fill banner.
- Planner `Header` logo now links to `/`. `RoutePlanner` reads its initial country/days from the

- `useTrip` gained `intent` (from the query string) and `ready`; `TripProvider` takes
  `initialIntent`. Restore failures no longer leave `ready` false (`fetchTrip().catch`).
- BFF `/api/browse` gained `resource=catalog-tours` and `resource=tour-route`.
- Root layout: Poppins + Fahkwang + Inter variables, theme restore script, `metadataBase`
  (`NEXT_PUBLIC_SITE_URL`, default `https://aa-tripplanner.vercel.app`), title template.

- Review round (S236): retired tours get `robots: noindex, follow`; JSON-LD activities moved from
  `touristType` to `keywords`; home has `alternates.canonical = "/"`; uppercase / non-canonical
  tour and destination slugs 308 to the lowercase slug; destination map pins exactly the 12
  listed places, `StaticMap` takes its caption as a prop; the error page has the site header and
  footer; `?tour/source/ask` leave the URL once the pre-fill prompt is answered
  (`history.replaceState`, other params kept); the planner list view asks before merging into a
  non-empty trip and pages with "Show more" (24 per page, `offset`).
- `dev_browse_server` port can be overridden with `DEV_BROWSE_PORT` (8011 was held by a stale run).

## Tradeoffs

- **Month filter in Python** over the country/duration-filtered rows instead of SQL: the catalog
  has no month column and `best_time_to_go` is free text; a few hundred rows per request, behind
  a 30-min CDN/ISR cache. Revisit if the catalog grows into thousands, or ask CIS for a month array.
- **Country intro from facts** (counts, day range, real places/activities), because contract v1
  has no editorial country text. Honest but plain; CIS destination content would replace it.
- **List view sits above the map filters** (needs the Map view to change country): simpler than
  re-flowing the filter panel, and the planner's map behaviour is untouched.
- **Home prerender at build**: if the browse read fails during a Vercel build, the home shows its
  error states until the next revalidate (≤ 30 min).

- **Kit contrast left as is** (review major 3): white on `#DB9628` (2.5:1), `accent-deep` on
  `accent-tint` (4.05:1) and `muted` on `bg` (4.43:1) fail WCAG AA, but they are the CIS kit's
  values; forking them here would split the family. Raised for a shared kit fix (e.g. ink text on
  gold primary, about 8:1).
- **Tour-by-slug query not restructured**: `catalog.v_tour.slug` is computed in the view, so the
  slug lookup may build `v_tour` for every tour. Fixing it needs a stored slug in CIS (or
  measuring first); left for `EXPLAIN ANALYZE` on Dev.

## Hotfix after PR #72 (S236 UI verify, branch `fix/aa-812-plan-tiles-customise`)

Evidence: root `docs/audits/2026-10-14-S236-design-review/ui-verify/` (D1–D5).

### Root causes

- **D1 — tile storm on /plan.** Not a regression of #72: `MapView.tsx` did not change in #72 (last
  touched by AA-674). `tilesForBounds()` listed every 1-degree cell in the viewport and
  `refreshVisibleTiles()` fetched them all at once with `Promise.all`. The map opens at
  `center [105, 15], zoom 3`; at 1440x900 the map area (1040 x ~844 px, 512-px Mapbox tiles) spans
  ~91 x ~68 degrees (lat -21.4 to 46.2), so one refresh = ~6,350 requests; the load refresh plus the next moveend gave
  the ~10,200 seen in 8 s. Chrome ran out of sockets (`ERR_INSUFFICIENT_RESOURCES`), the browse
  Lambda hit the 10-execution account limit (503, 1,591 throttles at 10:45 UTC), and because
  `fetchTile` let a network error reject, one failed tile rejected the whole `Promise.all`, so no
  pins were ever drawn. #72 only made it visible: the planner moved to `/plan`, the UI verify opened
  it on the prod alias, where the URL-restricted Mapbox token lets the map load (on deployment URLs
  Mapbox 403s, the map never loads and no tile is requested). S202 had already seen tile 503s at
  world zoom.
- **D2 — "Customise this trip" 404.** `/browse/tour-route` read only the Tour Graph
  (`tripplanner.tour_stop` / `itinerary_components`), keyed by the published tour_id of the day a
  tour was extracted, under the CURRENT catalog tour_id (`resolve_tour_id` prefers the id found by
  `source_id`). Two gaps: (1) coverage — the graph holds ~650 `tour_day` / ~620 `tour_stop` rows
  (well under 100 tours) against ~890 live catalog tours, so most tours were never extracted;
  (2) ids — a CIS re-upload gives a tour a new tour_id the graph does not know (all three failing
  tours have `tour_id ≠ source_id`, i.e. they are re-uploads). `source_group_id` is a fresh uuid
  (CIS migration 052), so `source_id` never equals an older tour_id either.

### Decisions

- **Tiles: coarse fixed grid, not a bbox endpoint.** Tile ids gain an optional size:
  `<lat>_<lng>_<size>`, size ∈ {1, 2, 5, 10, 30, 90} (each divides 90 and 180, corners must sit on
  the grid, so a tile has exactly one id and stays CDN-cacheable). 1-degree ids keep the historic
  `<lat>_<lng>` form (same CDN keys). Chosen over a bbox + server clustering endpoint: no new SQL,
  same cache model, and Mapbox already clusters client-side.
- **`frontend/lib/tileLoader.ts`** (no imports, unit-tested with `node --test`): `planTiles()` picks
  the finest grid that covers the view in ≤ 16 cells (a 90-degree grid is ≤ 8 cells for any view, so
  the bound always holds; antimeridian / world copies wrap). `TileLoader`: in-memory LRU cache per
  filter set, ≤ 4 requests in flight, the previous view's requests aborted on a new view, a failed
  tile counts as empty and is not cached (retried next view), and a **request budget** (64 per 10 s)
  as the loop guard — a re-render or effect loop cannot fan out again. `moveend` is debounced 250 ms.
  No min-zoom cut-off: at low zoom the few coarse tiles return the pins and Mapbox clusters them,
  which is the "country-level clusters" view.
- **`fetchTile` throws on non-2xx** so a 503 is not cached as an empty tile.
- **tour-route lookup chain**: (1) Tour Graph under the current tour_id, then under the tour_id the
  link carried (relabelled to the current id) — `match: "tour_graph"`; (2) else the tour's own
  places from `catalog.v_tour_place` (destination_id = `shared.destinations`, the same ids the
  planner's components use), each day pinned to a planner experience at that place, the tour's own
  components first, a different one per day of a stay — `match: "places"`; (3) else 404 with
  `tour` = title, country, length and day titles (`catalog.v_tour` + `v_tour_day`), which the
  planner shows under the pre-filled route finder. Only catalog views are read (ADR 0001); no
  silver/gold read was added to find older tour_ids of a source group.
- **D3**: the tofu boxes are emoji (no emoji font in the headless test browser; pre-existing, not
  caused by the move). Replaced the ones the audit saw (trip empty state, Tip line, mobile
  Explore / Your trip tabs, "Start from a route") with the kit `Icon` SVGs.

### Changed

- CI frontend job runs `npm test` (new script: `node --test --experimental-strip-types lib/*.test.ts`);
  `tsconfig` allows `.ts` import extensions (test file only; `noEmit` already on).
- `RouteProposal.match`, `TourRouteFallback`; `fetchTourRoute` returns `{ missing, tour }` instead of
  `"missing"`.

### Tradeoffs

- A "places" route pins experiences other AA tours offer at the tour's places, not the tour's own
  day plan. The applied message says so ("built from its places and our experiences there"); the
  advisor still gets the tour. Better than an empty trip; the real fix is extracting the tour into
  the Tour Graph (CIS AA-712 moves that pipeline).
- A 90/30-degree tile can return many pins (all destinations of a region); fine at today's size
  (~4k components), cached 30 min at the CDN.

### Should know

- **Deploy order**: both deploy on merge (Lambda workflow on `backend/**`, Vercel on main). Until
  the browse Lambda is updated, sized tile ids get 400 and low-zoom views show no pins (no storm:
  failures are bounded and not retried in a loop); 1-degree views work throughout.
- **D4 / D5 not code bugs**: the hero / list placeholder is `Photo` with no URL, i.e. the tour has
  no matched photo (`catalog.v_tour.cover_photo_path` NULL, `photo_count` 0); no photo URL was
  broken in the audit. Coverage is CIS photo matching (AA-708). Check on Dev:
  `SELECT count(*) FILTER (WHERE photo_count = 0), count(*) FROM catalog.v_tour`.
- **Verify live after deploy**: /plan on the prod alias at world zoom sends ≤ 16 tile requests per
  view (DevTools network), pins render, no 503; CloudWatch `Throttles` for the browse Lambda stays 0;
  `GET /api/browse?resource=tour-route&tour_id=…&source_id=…` for the Sri Lanka / Kailash / Agra
  tours of the audit → 200 (`match`) or 404 with `tour`.

### Review follow-ups (S236 review of `3a37e97`, verdict ship)

- **Partial views keep their pins** (review finding 1): `TileLoader.loadView()` now reports
  `complete` (false when a tile failed or the budget skipped tiles) and `retryAfterMs` (time until
  the budget window frees a slot). `MapView.refreshVisibleTiles` merges a partial result into the
  pins already drawn under the same filter scope instead of replacing them, and schedules exactly
  one retry (`max(3 s, retryAfterMs)`); a retry never schedules another, and any new moveend /
  filter change cancels it. So a 503, a 400 during the deploy window or an exhausted budget no
  longer blanks the map, and cannot start a retry loop (still bounded by the 64 / 10 s budget).
- **Filter/cache-key race** (finding 5): the fetcher now receives the filters `loadView()` was
  called with (`TileFetcher<T, C>` context argument), so the request and its cache scope always
  describe the same filter set. MapView no longer reads `filtersRef` inside the fetcher.
- `tileIdFor` (unused since the loader) removed from `lib/mapbox.ts`.
- New unit tests: partial-view reporting + retry delay, and the context hand-off (9/9 pass).
- **Not changed (product / deploy calls, tracked for the orchestrator)**: deploy order — the
  browse Lambda must be live before Vercel promotes, or low-zoom views show no pins (finding 2);
  the "older tour_id" key rarely helps re-uploads (finding 3); minimum day coverage before
  answering `match: "places"` (finding 4); the missing-tour copy mentions an advisor hand-off the
  box has no button for (finding 6). The read-only DB probe `rv812_probe.py` still has to be run
  before merge.

### S236 — places route needs half of the days (Nghiệp)
- `tour_route` offers a `match: "places"` route only when it pins at least 50% of the tour's days (`PLACES_MIN_DAY_SHARE`, days = max(duration_days, catalog day rows)). Thinner routes (Dev probe: Sri Lanka 2/10) answer 404 with the day list. The lasting fix is AA-712: the place pipeline moves to CIS as a job and runs for the whole catalog.

## S237 — photo fallbacks, contrast, month filter (branch `feat/aa-812-pdp-polish`)

Lane plan: root `docs/audits/2026-10-14-S237-lane-backlog/lanes.json` (tripplanner item 3). D3
(tofu icons) was already fixed in #73. Out of scope: the "from $X" price (waits for Booking
`v_from_prices`, AA-810/679) and the intensity filter (no intensity column in `catalog.v_tour`, so it
waits for CIS 228). Both stay as follow-ups on AA-812.

### Decisions

- **D4/D5 are a data gap, so the fix is a fallback in the API.** `fill_fallback_covers()` in
  `backend/browse/catalog.py` gives a tour with no cover of its own (a) the cover of its *main*
  destination, then (b) the best-covered destination of its country. The main destination is the
  one with the most itinerary days in `catalog.v_tour_place`, then the earliest day, then the name.
  For (b), "best covered" means `v_destination.photo_count` DESC, then the name. Only catalog views
  are read: `v_tour_place`, `v_destination` (ADR 0001).
- **The fallback is labelled and never shown as the tour.** New fields on cards and the tour
  answer: `cover_source` = `tour | destination | country | null` and `cover_place` = the
  destination's name. The tour hero gets a caption "Destination photo · <place>". Alt text is
  "<place> — destination photo" on the tour hero, the site `TourCard`, the List thumbnail and the
  OG image. The JSON-LD `image` still lists only the tour's own photos.
- **When the fallback runs**: only for the page being returned (list: after sort and slice;
  destination page: its top tours; tour page: only when the tour has **no** photos). A page where
  every tour has a cover runs no extra query. That makes at most 3 extra reads per response, all
  behind the 30-min CDN/ISR cache.
- **Country match is case-insensitive** (`lower(v_destination.country) = ANY(...)`), the same way
  CIS joins `shared.destinations` to a tour's country in migration 225 (`v_tour_place`).
  `v_destination` is small, so losing the plain-equality pushdown costs little.
- **Countries without any tour photo** (`/browse/catalog/destinations`) get their best-covered
  destination's photo. The destination page hero is a tour's own cover first, else the first
  gallery photo. It is picked *before* the listed tours get their fallbacks, so a real tour photo
  always wins.
- **D6 contrast: fork three light tokens** (this reverses the S236 "kit contrast left as is"
  tradeoff, now that the lane plan has a contrast fix in its Done-when). The tokens are
  `--aa-accent-deep` #9E6E16 → #875D12, `--aa-muted` #6B7380 → #656D7A, and `--aa-on-accent`
  #FFFFFF → #1A1206 (ink on the gold primary, as the dark theme already does). The ratios are in
  the `tokens.css` header. They are proposed back to the CIS kit under AA-655 so the family stays
  one palette.
- **Destination hero gets a solid dark layer** (`--aa-hero-bg`, Tailwind `k-hero-bg`) under its
  photo and scrim. The white hero text stays readable while the photo loads, if it fails, or if
  there is none. It also lets axe/Lighthouse measure the text against a real colour (it measured
  1.07:1 against the page background).
- **Month filter in the List view** (`TourListPane`, "Travel in": Any month / January to December)
  passes `month` to the existing `/browse/catalog/tours` filter (`months_from_text`). A tour whose
  text names no month stays in, as before. Changing the month resets the list and "Show more"
  keeps the month. If the result is empty, the message says no tours list that month.
- **Destination gallery alt** is "<place>, <country>" instead of the caption text
  (Lighthouse `image-redundant-alt`).

### Changed

- API: `cover_source` and `cover_place` on every tour card and on the tour answer. They are display
  helpers outside the `catalog.tour.v1` contract; `_contract_view` in the test strips them.
- `frontend/lib/text.ts`: `coverAlt()` and `MONTH_NAMES`, with a unit test in `lib/text.test.ts`.
  `fetchCatalogTours` takes `month`.
- Tests: `test_catalog.py` +9 (fallback order, the main-destination rank, no queries when every
  cover exists, placeholder kept when no place photo exists, tour hero, destination page, country
  list, case-insensitive country). `FakeCatalogPool` answers the two new SQL constants and takes
  `dest_photos`.

### Tradeoffs

- **A destination photo is better than a camera placeholder**, but it is not the tour. It is
  captioned on the hero and named in alt text. On cards it is only named in alt and title, because
  a caption on a 4:3 card thumbnail was too noisy. The real fix is CIS photo matching (AA-708).
- **The planner's own light palette (`aa-*` hex) is unchanged.** /plan buttons still use white on
  `#DB9628` ("Plan this route" in the List view, the route finder, the trip panel). The S237
  Done-when is about tour and destination pages, and recolouring the planner is the planner
  redesign (AA-674).

### Should know

- **Deploy order**: the frontend tolerates a browse Lambda without the new fields. `cover_source`
  is then undefined, so alt falls back to the title and there is no caption, the same as before.
  Either order is safe.
- **Evidence**: root `docs/audits/2026-10-14-S237-lane-backlog/ui-verify/tp-812/` has local
  fixture-build screenshots, axe and Lighthouse 100/100. The Done-when still needs the **prod alias

- `/favicon.ico` 404s (there is no favicon; this was true before this change). It is a separate
