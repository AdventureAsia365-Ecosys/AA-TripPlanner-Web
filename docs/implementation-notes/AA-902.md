# AA-902: no AWS account IDs or ARNs in this public repo

## Decisions

- **Satellite account IDs have no code default.** `backend/config.py` reads `BEDROCK_ACCT_PRIMARY` /
  `BEDROCK_ACCT_FALLBACK` from the Lambda environment with an empty default. `llm_gateway._satellite_target`
  raises a `BedrockError` naming the unset variable before any STS call, so the failover loop logs it and moves on
  (acc2 and the other satellite still serve). No new variable names: both already existed and the assembly Lambda
  sets them in AA-CIS-Infra `tripplanner.tf`.
- **Deploy role ARN is a repo secret.** `deploy-lambdas.yml` reads `secrets.AWS_DEPLOY_ROLE_ARN` (fails with a clear
  error when unset) instead of a literal fallback. A secret, not a variable, because the run logs of a public repo
  are public: a secret is masked, a variable is printed in the step's `with:` block.
- **Artifacts bucket is derived after login:** `aa-tripplanner-dev-lambda-artifacts-<account>`, with the account from
  `sts get-caller-identity`, masked with `::add-mask::` and `mask-aws-account-id: true`. The optional repo variable
  `LAMBDA_ARTIFACTS_BUCKET` still overrides it.
- **Blocking check:** `.github/scripts/check_resource_ids.py` (stdlib, same file as AA-Booking) runs as the first
  step of the required `Backend (pytest)` job, so a finding blocks the merge without a new required check. It scans
  every tracked text file with the AA-Ecosys docs-lint resource-ID patterns, plus a 12-digit number after `-`.
- **Allowlist:** `123456789012`, one repeated digit (the `111111111111` / `222222222222` test fakes stay), the last
  group of a UUID, a user-pool ID that says TEST/EXAMPLE, and lines carrying `docs-lint: ignore`.

## Tradeoffs

- Removing the defaults moves the account IDs to configuration that must exist before this code ships. The browse
  Lambda relied on the defaults (AA-862 note), so AA-CIS-Infra has to add the two variables to it first; if it does
  not, browse only loses the acc3/acc1 embed fall-through (acc2 embedding still works), it does not break.
- Secret vs variable for the role ARN: a secret cannot be read back in the UI, but it keeps the account ID out of
  public logs, which is the point of AA-902.

## Should know

- Order before merge: (1) AA-CIS-Infra: `BEDROCK_ACCT_PRIMARY` / `BEDROCK_ACCT_FALLBACK` on the browse Lambda
  (same values as assembly), applied; (2) repo secret `AWS_DEPLOY_ROLE_ARN` set (Terraform output of
  `aws_iam_role.tripplanner_app_deploy`). Merging touches `backend/**`, so deploy-lambdas runs right away.
- Git history and old Actions logs still hold the account IDs. AA-902 scope 5: no history rewrite proposed.
- To check locally: `python3 .github/scripts/check_resource_ids.py` from the repo root (exit 1 on a finding; IDs in
  the output are masked).
