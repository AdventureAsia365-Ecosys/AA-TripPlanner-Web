# AA-986 L6 — saved trips, the tour page and the hand-off when AA no longer serves a tour (TripPlanner)

Slice L6 of root ADR 0015 (tour liveness and retirement propagation), decision 5 "AA-TripPlanner-Web" and Q5.
Contracts: `catalog.tour.v1.3` (CIS 274: `catalog.v_tour_retired`, written by slice L4) and
`inquiry.submitted.v1.3` (this slice; AA-Ecosys `docs/contracts/inquiry.submitted.v1.3.json`, vendored as
`backend/tests/contracts/inquiry.submitted.v1.3.json`).

## Decisions

- **What happens today, before L6:** the trip's components come from `catalog.v_tour_component`, live tours only, so a
  pinned stop of a retired tour silently **disappears** from the saved trip (not "shown as normal", as the audit memo
  row says: that was true of the frozen tripplanner tables, gone since AA-712 X4). L6 makes it visible instead.
- **Unavailable stops are listed apart, not mixed into `itinerary`.** `GET /trip/{id}` returns `itinerary` (served
  stops, each `available: true, reason: null`) and `unavailable_stops` (`available: false` + `reason` +
  `reason_detail`). Putting them in `itinerary` would make every consumer (map pins, legs, coverage, narration cache
  key, sequencing) filter them; a separate list leaves all of that unchanged.
- **Reasons** (`backend/assembly/availability.py`): served key but stop gone → `stop_removed`; tombstone `retired` →
  `retired`; any other tombstone state (`paused`, `superseded`) → `paused` (ADR: shown as paused / superseded_pending
  until `publish` writes `restored`); otherwise `not_served`. `catalog.v_tour` wins over a tombstone row (the probe
  owns that inconsistency).
- **How a stop is named after it left the catalog.** The catalog no longer returns its row, and `geo.tour_place` is
  not granted to `tripplanner`. So the `trip_drafts.itinerary` projection (jsonb, already `pii:travel`) now stores per
  stop: name, `source_tour_id` (= catalog `source_id` since the AA-847 flip), tour day, destination id / name, lat /
  lng, `available`. On every rewrite an unavailable stop is **carried over** from the previous projection
  (`available: false`), so it keeps its name across later edits. No migration (jsonb shape only; no reader of the
  projection besides `events.py`).
- **Drafts written before L6** have no tour key in the projection: such a stop is listed with its saved name and
  `not_served`. Dev has no real travellers (memory `dev-no-waiting`), so no back-fill.
- **Removing a greyed stop** uses the normal `DELETE /trip/{id}/components/{cid}`: the fold is by event ids, so it
  works although the catalog does not serve the component.
- **Hand-off v1.3.** Every leg and day carries `available`, `reason`, `reason_detail` (required in v1.3). Unavailable
  stops go **after** the served days / legs (their last known trip day, or the day after the last served day), so
  they never split a served leg. Their leg's `source_system` / `source_id` come from the tombstone (`cis`, key) when
  the key is known; else null, as for any unresolved key. The hand-off is never refused over availability.
- **410 for a retired tour page via `proxy.ts`.** Next 16 has `notFound` (404), `forbidden`, `unauthorized` and
  redirects, no "gone". The only way to answer 410 on `/tours/<slug>` is the request proxy. To keep a tour page view
  at one Set lookup, the proxy holds the retired slug suffixes in memory (`lib/goneTours.ts`), read from
  `GET /browse/catalog/retired` every 30 min (failed refresh: keep the last list, retry after 60 s, 1.5 s timeout).
  A suffix shared with a live tour is never listed. Paused → 404 (ADR: temporary). The browse Lambda also answers
  `/browse/catalog/tours/{slug}` 410 for a retired key; the page turns that into 404 (stale proxy list window).
- **Superseded = nothing to build.** The slug suffix is the first 8 hex of the stable `source_id` (CIS 253), so an old
  slug finds the current version and the page `permanentRedirect`s. Next answers **308**, not 301; search engines
  treat 308 as 301 (permanent). Kept.

## Changed (vs. the slice text)

- "301 to the current slug": answered 308 (Next's permanent redirect), already in place before L6.
- `lifecycle_stage = 'retired'` filters (lists, sitemap, page noindex/badge, ADR Q9) were left as they are: nothing
  writes that column and the lists already read the served state through `catalog.v_tour`; removing the filter is a
  no-op for data and only churns tests. Candidate clean-up later.

## Tradeoffs

- The proxy now runs for every `/tours/<slug>` request (Vercel Routing Middleware runs before the CDN cache). Cost:
  one function invocation of a few ms per tour page view, no network except one browse call per 30 min per instance;
  inside the Hobby included usage at today's traffic (≈ $0). Alternative rejected: redirect retired pages to a 410
  URL (307/308 then 410 on another URL) — the URL itself would not answer 410.
- `available: true` is added to served stops in the `GET /trip` answer only (not in `current_itinerary`), so the
  narration cache key does not change.
