# AA-877: DM-6.1 tags on the TripPlanner columns (tp-016)

## Decisions

- **COMMENT ON COLUMN only, one file (tp-016).** Static statements, a `current_user = 'tp_owner'` guard, the
  `shared.schema_versions` row. No grant, no DDL, no role switch; passes `migration_lint.py` and the Infra
  `run_migration.py --inspect` lint.
- **Key tp-016.** CONTEXT.md had reserved "tp-016 or later" for the slice 6c component id-map migration, and AA-861
  (`tripplanner.job`) needs a key too. This file takes tp-016; the slice 6c note now says tp-017 or later. The
  orchestrator confirms the number before the PR (renumbering is cheap until the Infra byte copy exists).
- **Tags** (from the code, not only column names):
  - `customers.name` pii:name; `customers.phone` / `email` pii:contact.
  - `outbox.payload` and `v_inquiry_outbox.payload` pii:contact, also pii:name, pii:free_text, pii:travel
    (contract inquiry.submitted v1.2: customer, itinerary with dates, custom day notes). The 90-day redaction is
    approved but not built until `tripplanner.job` (AA-861); the comment says so.
  - `trip_drafts.itinerary` pii:travel, also pii:free_text (custom day notes); `date_start` / `date_end` pii:travel.
  - `trip_events.payload` pii:free_text, also pii:travel: only `add_day` carries personal content (the traveller
    note, up to 500 chars, `backend/assembly/handler.py`); other event types carry ids.
  - `sessions.guest_token` / `guest_token_hash` conf:credential, restated from the tp-011 form
    `'conf:credential — …'` to `'conf:credential; …'`, the text after the separator unchanged.
- **Left untagged**: `sessions.customer_id`, `trip_events.session_id` / `trip_id`, consent flags, timestamps, the
  frozen catalog read model (`tour_*`, `itinerary_components`, `narration_cache`), `llm_spend_daily`.

- Name-based checks cannot see PII inside jsonb; the explicit map from the code reading is the evidence.
