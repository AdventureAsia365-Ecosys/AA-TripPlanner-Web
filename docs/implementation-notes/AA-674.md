# AA-674 — Multi-tour composition + route-constrained "suggest next" (PR-11)

## Step 1 — rebuild itinerary_components for the active tours

### Decisions
- **From atoms, deterministic** (`backend/extraction/components.py`, op `components`): each atom
  already carries `place` + `activity_type`, so `categorize_atom` maps it to one component with no
  model call. Lodging and transit "places" are skipped (the same rule as the night anchor).
- **Places are linked through `locate.py`**: rows located before (`located_by`, migration 005)
  are reused by name; legacy rows and new names are located (model + Mapbox, one call per 40
  names). Components whose place cannot be located are dropped.
- **Embeddings** via `tp_component_embed`, 96 texts per call, logged. Search and taste ranking
  read `embedding IS NOT NULL` rows only.
- **Replace per tour in one transaction**, one tour per Lambda invoke. Only active tours are
  touched; the 1,081 legacy components of unpublished tours stay until an opt-in prune.
- Reading atoms needs CIS migration 180 (column grant to `tripplanner`).

### Tradeoffs
- Deterministic mapping gives every component `full_day` and all 12 months. The atoms have no

  activity filters; seasons can come later from `season_note`.

## Step 2 — route-constrained "suggest next"

### Decisions
- **Candidates follow real tours** (`ROUTE_CANDIDATES_SQL` in `backend/assembly/suggestions.py`):
  - take every `tour_stop` within `JUNCTION_KM` (150) of the trip's last stop (the last stop is
    sequenced as before);
  - for each such tour, the candidates are the components of the days after that stop, up to the
    tour's next stop at a different destination (a multi-night stay is skipped over).
  So a suggestion is always "what an Adventure Asia tour does next from here", and a stop
  > 1 km away is a transfer to another tour (the chaining PR-11 asks for).
- **Ranking unchanged**: taste (pgvector) blended with distance to the last stop. The candidate
  pool is just narrower.
- **Fallback** to the old taste-in-trip-countries query when no tour passes near the last stop.
  The response says which one ran (`mode`).
- The "next stop" is the tour's next stop *elsewhere than that stop*, not outside the whole
  150 km circle. The first version used the circle and returned nothing in Bhutan, where Paro,
  Thimphu and Punakha all sit within 150 km of each other.

### Changed
- Fixed: `events._current_components` did not select `destination_id`, so pinned destinations
  were never excluded from suggestions.

### Should know
- Measured on Dev as the `tripplanner` role: ~25 ms. From Kathmandu: Lukla, Pokhara, Namche
  Bazaar, Phakding, Everest Base Camp. From Thimphu: Kurje Lhakhang, Kyichu Lhakhang, Buddha
  Dordenma.
- Filters (country, activity, intensity, duration) and whole-leg-chain suggestions are step 3.
