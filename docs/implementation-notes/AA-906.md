# AA-906 — Next.js 15 → 16, React Compiler lint refactor (S248)

Follow-up of AA-904 (Next 14 → 15). Branch `feat/aa906-next16`. Frontend only (`frontend/**`); no
backend, no migration, no AWS change.

## Decisions

- **Versions: `next` 16.4.2 and `eslint-config-next` 16.4.2** (latest stable on 2026-10-23, same `next`
  as the CIS admin and portal; Booking is on 16.3.8). eslint-config-next is kept equal to `next`
  (CIS still has 16.2.4 — harmless, not changed here). ESLint stays on 9 (eslint-config-next 16 peers
  `>=9`; CIS and Booking are on `^9`), although npm now flags 9.39 as out of support — a separate bump.
- **Official codemod for the rename:** `npx @next/codemod@16.4.2 middleware-to-proxy .` renamed
  `middleware.ts` → `proxy.ts` and the exported function `middleware` → `proxy`; nothing else. Comments
  that named `middleware.ts` (guestToken, tripProxy, the trip BFF route, instrumentation) now name
  `proxy.ts`. The `next-lint-to-eslint-cli` codemod was not needed (AA-904 already moved to the CLI).
- **Native flat config** (`eslint/config` `defineConfig` + `eslint-config-next/core-web-vitals`), the
  FlatCompat bridge and `@eslint/eslintrc` removed. Same preset as before; the `typescript` preset
  that CIS adds was **not** added (it would bring new rules beyond the scope of this upgrade).
- **postcss override removed.** Next 16.4.2 depends on postcss 8.5.23 (no advisory); the
  `postcss-selector-parser` 7.1.6 pin under Tailwind 3 stays (unrelated to Next).
- **tsconfig.json**: committed the two edits `next build` makes on Next 16 (`jsx: react-jsx`, include
  `.next/dev/types/**/*.ts`), in the file's compact style, so a CI build no longer rewrites it.
- **The 23 React Compiler lint errors are fixed by refactor, no new rule disable.** Patterns used:
  - *Lazy state init instead of a ref read during render* — `useTrip` guest ids:
    `useState(loadOrCreateIds)` (fixed for the provider's life; same SSR/hydration behaviour as the
    old `useRef` lazy init: both run on the client during hydration and read localStorage).
  - *Ref sync after commit instead of a ref write during render* — `useTrip.filtersRef`,
    `MapView.filtersRef` / `searchResultsRef`: `useLayoutEffect(() => { ref.current = value })`. A
    layout effect runs before every passive effect in the tree, so the effects that re-query on a
    filter change (and FilterChips' debounced `runSearch`) still read the new value.
  - *`ref.current === null` lazy init* (the form React documents and the lint accepts) for the
    MapView `TileLoader`.
  - *Derived state: tag an async result with the key it was fetched for* — `DestinationPopup`
    (`loading = fetched.id !== destinationId`; the previous detail still shows until the new one
    lands, as before), `TourListPane` (page + "add to your trip?" question tagged with
    `country|month|sort|attempt`), `TripPanel` narration reveal (`{text, n}`).
  - *"Adjust state when a prop changes" during render* (guarded, once per new key) — `useTrip`
    clears suggestions / coverage when the trip empties, `TripPanel` clears travel legs below two
    stops, `MapView` opens the popup for a new `focusDestinationId` (the effect keeps only the camera
    move and hands the request back with `focusDestination(null)`).
  - *Self-reference before declaration* (`immutability`) — `MapView.refreshVisibleTiles` retried
    itself from a timer; the body is now an inner `run` that the retry calls (same closure, same
    behaviour).
  - *External store* — `GuestResetNotice` reads the one-shot reset notice from sessionStorage with
    `useSyncExternalStore` (server/hydration snapshot `null`), instead of copying it into state from a
    mount effect. Live notices (`showGuestNotice` events) stay in state, set from the event callback.
- **The React Compiler itself stays off** (no `babel-plugin-react-compiler`, no `reactCompiler`
  option): the issue asks for the lint refactor, and turning the compiler on is a separate
  performance decision with its own build-time cost.

## Tradeoffs

- **Pre-existing `eslint-disable-next-line react-hooks/exhaustive-deps`** stay in TripPanel (legs effect
  keyed on `legKey`), PlanPrefill and RoutePlanner; the one in useTrip (coverage) is gone — the effect
  now lists the derived `tripEmpty`. They are the classic exhaustive-deps rule (a string key as the
  trigger to avoid refetching on identical data), not React Compiler rules; no disable was added.
  Note for a future React Compiler switch-on: the compiler skips a component that disables a
  react-hooks rule, so those three would then need the same treatment.
- **Render-time state adjustment vs. a key-tag** for the "emptied" cases: a key-tag alone would show
  stale suggestions / legs / coverage for a moment when a trip goes from empty back to non-empty;
  the render-time adjustment reproduces the old behaviour exactly and costs no extra commit (React
  re-renders the component before committing).
- **`TourListPane` "Show more"** now appends only if the query has not changed meanwhile (the old code
  could write an old query's page over the new query's loading state). Small behaviour fix that falls
  out of the key-tag.
- **`GuestResetNotice`**: the page-load notice is memoised per JS page load (module variable), so a
  client-side navigation away and back to `/plan` before its 6 s timer ends shows it again for 6 s
  (before, it was gone after the first mount). A full reload — what `resetGuestIds` does — starts
  fresh, as before. Accepted: rare and harmless.

  and builds with Turbopack (default `next build` in 16). Node ≥ 20.9 is required: CI uses Node 22,
  the Vercel project `aa-tripplanner` is set to Node 24.x (read 2026-10-23) — both fine.

  the build output lists it as "ƒ Proxy (Middleware)". No env var changes.

  `x-middleware-set-cookie`); `/` sets no cookie; a cross-site POST to `/api/trip` → 403
  `cross_origin`; with an echo upstream, a GET `/api/trip` without cookie forwards the minted token and

  on `/plan` (1280 and 390 px): no hydration error, page-load notice shows, a live notice replaces it,
  not shown again after reload, guest ids stable across reload.
