# AA-1143 — TripPlanner reads its own connection budget share (lane l11, S285)

Tech lead decision G3: one budget per LLM connection as rows in CIS (the total, one share per app, CIS takes the
remainder), edited on CIS AI gateway › Budgets. Full design: AA-CIS-App `docs/implementation-notes/AA-1143.md`.

## Decisions

- TripPlanner reads `catalog.v_llm_connection_cap_v2` (CIS 456), the control plane it already reads (root ADR 0009
  d13): one row per connection with a total, `app = 'tripplanner'`, by column name. No new grant beyond the view's
  `SELECT` to `tripplanner`.
- Log only first: `tripplanner.spend.connection_share_enforce` (CIS 456, bool, default false, maker-checker). On, and
  under the dev spend rules, `deployment_plan` leaves an over-share connection out (the route goes on with the next
  connection, as for an open circuit); under prod it only logs.
- Fail open like the app profile: the view missing or not granted (42P01 / 42501) or a read error = no share known.
  The CIS gateway still enforces the CIS remainder, and today TripPlanner has no share of its own (it spends inside
  that remainder), so nothing changes on deploy.
- `deployment_plan`'s skip checks moved into `_left_out` (share, then circuit) to keep its complexity under the
  ratchet (the baseline entry is lowered).

## Should know

- Deploy after the CIS migration batch 455-456; before it the reader is quiet (view missing).
- Turning enforcement on is a Platform › Settings change (TripPlanner tab), after the tech lead gives TripPlanner a
  share on Budgets and the log lines show it fits.
