# AA-1090 — TripPlanner R8: an agency's own domain serves its planner

Lane l12-tp-domain of S281 (root ADR 0019 b4 / d10; tech lead S278 D10 / D13 NEW-D). This repo's part: resolve a
request's Host to the agency tenant and map its paths onto the tenant's pages. CIS owns the hosts (CIS 427), their
certificates and the CloudFront aliases (the `tripplanner_custom_domain` job); AA-CIS-Infra routes every alias of the
distribution to this service.

## Decisions

- **Host lookup through the existing contract.** `catalog.v_tenant_tripplanner_v1` (already read for `/{slug}`) gains
  `custom_domains` (CIS 428); the browse Lambda answers `GET /browse/tenant-host/{host}` with the same tenant shape as
  `/browse/tenant/{slug}`. No new view, no new grant, no new secret.
- **Our hosts stay on the old path.** `isOwnHost`: the public host of `NEXT_PUBLIC_SITE_URL`, localhost, IP literals
  and one-label names (the container and target-group health checks). Only another host is looked up, so a deploy of
  this code changes nothing until CIS runs the job and Infra routes the alias.
- **Unknown host = plain 404 page**, never AA's site (an agency's domain must not show AA's brand or another agency).
- **Path mapping by internal rewrite**: `/` -> `/{slug}`, `/plan...` -> `/{slug}/plan...`, `/tours/{tour}` ->
  `/{slug}/tours/{tour}`. The tenant's pages, BFF tenant assertion (the planner still names its slug), branding,
  tours, lead route and guest cookie are exactly those of `/{slug}`; `/{slug}/...` keeps working on both hosts. AA's
  catalogue pages and another tenant's `/{slug}` are 404 on an agency's domain.
- **Matcher**: every path but `_next/static` and `_next/image` (a Host decides, whatever the path). On our host the proxy
  still acts only on the old paths (`actsOn`, the old matcher as literals), so the behaviour there is unchanged.

## Changed

- `backend/browse/tenant_site.py` (`HOST_SQL`, `lookup_host`, 42703 = absent column = 404), `backend/browse/handler.py`
  (route + route name `tenant_host`).
- `frontend/lib/tenantHost.ts` (host helpers, path mapping, cached resolver, the two plain pages), `frontend/proxy.ts`.
- Tests: `backend/tests/test_aa1090_tenant_host.py`, `backend/tests/test_aa1090_tenant_host_pg.py` (stand-in view with
  the CIS 428 columns, copied from the CIS test), `frontend/lib/tenantHost.test.ts`.

## Tradeoffs

- A lookup per host per minute per instance (cached), against a per-request header from the edge: the edge cannot
  know the tenant, and the cache keeps the browse load at one read a minute per host.
- The canonical URL of a tenant page still names our host (`NEXT_PUBLIC_SITE_URL/{slug}`): fine for Dev; a per-host
  canonical and sitemap are follow-ups.

## Should know

- Nothing reaches this code from an agency's domain until AA-CIS-Infra is applied (cost approval pending) and a host
  is active in CIS.
- The WAF rules move from the Host to the per-distribution site header in AA-CIS-Infra, so they apply to every alias.
