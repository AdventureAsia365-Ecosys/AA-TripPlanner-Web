## Decisions

- **E5 (1) confirmed by grep before the change.** On main the only reads of `shared.llm_role_config` /
  `shared.llm_model_catalog` were `_route_from_tables` (the pre-323 fallback on SQLSTATE 42P01 / 42501) and the only
  use of `tripplanner.llm_spend_daily` was the counter upsert in `record()` plus the pre-323 spend fallback in
  `_spent()`. Nothing in `tools/`, `scripts/`, `frontend/` or the Lambda entry points (`browse/`, `assembly/`,
  `jobs/`) names them. The live view read is shown by the E3 evidence (S264: ledger rows with deployment wire ids that
  only the view carries); the orchestrator's live step re-checks it in CloudWatch (no `"not readable yet"` gateway
  note) before this PR merges.
- **Fail closed, no new degrade path.** A missing / ungranted / failing view now raises into the existing
  `AiPaused("route_unreadable")` (route) or `spend_unreadable` (budget): narration answers basic + `ai_paused`, search
  answers the keyword ranking. Same behaviour as any other config read error since AA-642 S0.
- **The counter write is removed in the same PR** (not only the fallback read): the spend view sums the ledger, the
  counter was a second record only. A lost ledger row of an online stage still pauses AI for 60 s (unchanged).
- **Column sets instead of a single 42703 fallback.** The view read tries 323+341+350, then 323+341, then the 323
  contract columns; each narrowing is cached for `VIEW_RETRY_SECONDS`. So this PR can merge before CIS 350 is
  applied (it runs as today until then).
- **E4 shape: two appended view columns** (`supports_temperature boolean`, `stage_params jsonb`), not five typed
  columns: one object per stage x model mirrors `deployments` / `deployment_routing`, and a later field of
  `stage_model_params` is appended inside the object without a new view column.
- **Precedence = CIS `shared/llm_client/stage_params.py`.** The TripPlanner call site (assembly narration) always
  passes `max_tokens`, so the row's `max_tokens` / `min_output_tokens` never apply (said once). Temperature only when
  the catalog says `supports_temperature` true (None = not sent: Sonnet / Opus 5.5 refuse a sampling parameter).
  Effort is never sent (review fix): every TripPlanner attempt is a Bedrock call, and CIS sends effort only on the
  Anthropic Messages API, never on Bedrock InvokeModel or Converse (`stage_params_not_applied` until a probe has shown
  the provider's field). An effort row is said once (`llm_stage_params_not_applied`) and the ledger `effort` stays
  NULL. `reasoning_mode` never.
- **Kill switch** `LLM_STAGE_PARAMS` (same name as CIS), default on, read at import.

## Tradeoffs

- Effort on Bedrock is not sent at all. The first build sent `output_config.effort` on the Anthropic-native
  InvokeModel body; review pointed out no probe had shown Bedrock accepts it (CIS never sends it there), and a
  rejected body would fail every attempt and drop every traveller to the basic narration. Cost: an admin effort row
  has no effect on TripPlanner until a probe (or a catalog capability flag) adds the field back; the warning line says
  so. `Call.effort` and `_with_params` stay so that adding it back is a one-line change in `request_params`.
- Keeping the 323-only column set costs nothing and keeps old fixtures meaningful; 341 is live, so in practice the
  read is 350 or 341.
