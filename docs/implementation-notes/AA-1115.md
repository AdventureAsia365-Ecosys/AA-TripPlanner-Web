# AA-1115: agency-only branding, html lang, the traveller sign-in retired, the compose-body guard

S282 progress report (G19, G4, G9, G23, G24) and the S282 audit section 6.3: TripPlanner reaches agencies only through
the hosted planner `/{slug}/plan`, agency pages still showed "Adventure Asia" strings, `html lang` ignored the tenant
locale, and the B2C pages `/sign-in` and `/trips` were still reachable. Root ADR 0019 d10 / d11. `tp.ai_sessions` is
already enforced (AA-1116, TripPlanner #271) and is not part of this change. The launcher snippet is the AA-Partner
half of the issue (agency Add-ons page).

## Decisions

- **One place for the brand words.** `frontend/lib/brand.ts` holds every sentence that names Adventure Asia:
  `AA_*` exports for AA's own site (root metadata, the AA bar, the site AI pill, the catalogue AI label, the legal
  contact) and `brandCopy(agency)` for the words the planner's shared components show (narration badge, catalogue
  AI label, "built from N tours", next-stops caption, the AA form's consent, the BO-8 badge). Components read it
  through `components/BrandContext.tsx`, which `PlannerApp` provides for an agency's planner. A React context, not
  the tab's module state (`lib/plannerTenant.ts`), because that state is set only in the browser: the server render
  of an agency's planner would have carried AA's words.
- **Neutral wording where both sites can share it.** The AI-paused notices (EN and VI), the route finder, the tour
  list, the retired-stop banner, the chat intro (EN and VI), the demo notice and the preview footer line no longer
  name a brand on either site, instead of branching per site.
- **Metadata from the /{slug} layout.** `app/[tenant]/layout.tsx` `generateMetadata` = `tenantMetadata(site)`:
  title default and template `%s · <agency>`, description, og:site_name (and og:locale), replacing every
  brand-bearing key of the root layout's defaults. Pages under /{slug} set only their own title (they used to add
  "· <agency>" themselves, which the template now does). A slug that does not resolve gets a neutral title.
- **html lang without a second root layout.** The root layout renders `<html lang="en">` for every page. Making it
  read the tenant (headers or params) would make every AA page dynamic; two root layouts would move every AA page
  into a route group, break the reserved-slug pin and need the experimental global not-found. So the /{slug}
  layout marks its content with the locale on the server (`<div lang>` with `display: contents`), sets `<html lang>`
  before paint with an inline script (as the root layout's theme script), and `components/TenantLang.tsx` keeps it
  on a client-side navigation and gives "en" back on unmount.
- **Agency legal pages.** `/{slug}/privacy` and `/{slug}/terms` (`components/AgencyLegalPage.tsx`): drafts that name
  the agency only, the agency as the controller of the trips sent to it, the facts of the code (guest and security
  cookies, AI calls, the lead hand-off with no copy kept), open points `[to be confirmed]`, the terms' `#ai` section
  with the Anthropic Usage Policy link. The AA-hosted demo tenant is redirected to AA's pages. The lead form now
  links them (it collected personal data without a legal link before); the planner's AI notices link
  `/{slug}/terms#ai` (`lib/legal.ts` `legalPaths`).
- **The share view and the agency 404.** `/{slug}/plan/shared` rendered AA's bar: now the agency bar. A page under
  /{slug} that was not found fell to AA's 404 page (AA bar, footer, catalogue links) on the agency's own domain: now
  `components/TenantNotFound.tsx`, a plain kit empty state with one way back (the agency's planner, from the address
  bar), shown by the not-found files of `app/[tenant]/tours/[tour]`, `plan` (covers `plan/shared`), `privacy`,
  `terms` and the catch-all `app/[tenant]/[...rest]` (always a 404: `/{slug}/destinations`, `/{slug}/plan/x`,
  `/{slug}/tours/a/b` reach it instead of the root 404). The bare `/{slug}` with an unknown slug keeps AA's 404 (no
  agency to brand; AA's own 404 for unknown top-level paths stays), and so do its sub-paths: `app/[tenant]/layout.tsx`
  calls `notFound()` for a slug that is no served tenant, so `/{bogus}/x` on AA's host is AA's 404 as before, never
  the agency 404 with a "Plan a trip" link to a planner that does not exist (a lookup that cannot answer still
  renders and the page throws it to `error.tsx`). Review fix (S283).
- **An agency's domain maps only real pages.** `lib/tenantHost.ts` rewrites exactly `/`, `/plan`, `/plan/shared`,
  `/tours/{one segment}`, `/privacy`, `/terms` (and lets the same pages through under `/{slug}`); any other path
  (`/plan/foo`, `/tours/a/b`, `/{slug}/unknown`) is the plain host 404 the proxy answers itself. Review fix (S283).
- **Backend text an agency's traveller sees is brand-neutral.** The chat's server replies
  (`plan_chat.fallback_reply`: "Here is a plan made only from the tours on this planner", "I can only plan with the
  tours and places on this planner. This planner has trips in ..."), the coverage gap reason ("no tour links these
  two places") and the suggestion "why" ("Next on N tours from your last stop") no longer name Adventure Asia, on
  either site (neutral wording, like the frontend's shared notices). The last three frontend "AA" literals ("no AA
  link", the "AA tour" fallback of the route list, "on N AA tours" and "No other AA activities here.") go through
  `brandCopy` (`coverage.noLink`, `coverage.unnamedTour`, `activities`). Review fix (S283).
- **The guard** (`frontend/lib/agencyBrand.test.ts`, `npm test`): walks the imports of every `app/[tenant]` file and
  the root layout; only `lib/brand.ts` may spell "Adventure Asia" / "adventure.asia" (comments excluded, a brand
  split over two lines included), nor show "AA" as a word in its code or copy (S283); only `components/Header.tsx` (the AA bar, never rendered with an agency) and
  `components/BrandContext.tsx` (the default) may use AA's own words; `brandCopy(name)` and `tenantMetadata` never
  return the brand or the word "AA"; the /{slug} layout sets metadata and language; every /{slug} page that can call
  `notFound()` has a not-found file below `app/[tenant]` (the bare `/{slug}` is the listed exception) and the
  catch-all exists. The backend twin, `backend/tests/test_aa1115_traveller_text_brand.py`, reads every string literal
  of `backend/assembly` and `backend/browse` (docstrings excluded) and fails on the brand or "AA" as a word unless an
  allow-list entry says why it never reaches an agency's traveller (the model prompts, the AA demo's send answer, the
  lead e-mail to the agency, the staff subject, the AI mark's generator name, which no page renders). Source-level, because the
  frontend tests run without a renderer (node --test, type stripping).
- **Compose-body guard** (`backend/tests/test_aa1115_compose_body_guard.py`, audit item "tp_compose: does it pass
  scrub_text"): the `tp_compose` prompt reads only `day`, `name`, `text_extract` of each entry (AST of
  `agent._build_body`), the prompt functions take no traveller input, the itinerary entry carries catalogue and
  position keys only, and the component read selects only `catalog.v_tour_component` / `catalog.v_destination`; an
  injected invoker shows that personal sentinels on an entry never reach the prompt. So the prompt needs no scrub.
- **The traveller sign-in is retired in the web app, not hidden.** `app/sign-in`, `app/trips`, the account BFF
  (`/api/auth/*`, `/api/me`), the Cognito client, the sealed session cookies, `AccountLink`, `MyTrips`,
  `SignInForm` and `useAccount` are deleted. `/api/trip` and the search of `/api/browse` no longer read a session
  cookie, forward an access token (`x-tripplanner-access`) or a signed-in flag (`x-tp-signed-in`). The send form
  always asks for the e-mail (no read-only signed-in e-mail).
- **The old paths stay reserved.** `lib/tenantSlug.ts` `RETIRED_PATH_SLUGS` (`sign-in`, `trips`) are still in
  `RESERVED_TENANT_SLUGS`, so `/sign-in` and `/trips` are the 404 page without a tenant lookup and can never become
  a tenant's site. The reserved-list test now pins "app/ folders + public/ entries + the retired paths" and checks
  the retired paths have no folder.
- **On an agency's domain** `/sign-in` and `/trips` are the plain 404 (they no longer pass), and `/privacy`, `/terms`
  are rewritten to the agency's own legal pages `/{slug}/privacy`, `/{slug}/terms` (below), never AA's.

## Tradeoffs

- **The model prompts still present the model as Adventure Asia's** (S283 review item (d)): the narration model reads "You are an Adventure Asia trip narrator" (`backend/assembly/agent.py`
  `_COMPOSE_SYSTEM` / `_RENARRATE_SYSTEM`, and the chat's system prompt). The prompt itself is never shown, but the
  model could name the brand in an agency's narration. Changing it moves the `tp_compose` prompt hash (registry gate
  and the CIS prompt register row), so it is a follow-up with its own version bump, not part of this change.
- The agency legal pages are drafts with the agency's open points; the agency (controller) must approve or replace
  them. The site has no field for the agency's own policy URL yet.
- **Backend left as is.** The assembly Lambda still has `POST /me/claim`, `GET /me/trips` and the account guards
  (`account_ok`, `account_read_ok`). Nothing calls them any more (no access token reaches the Lambda, so every answer
  is the guest one). Removing them, the `traveller_accounts` table (tp-019) and the Infra side (Cognito EXTERNAL
  traveller client, the pre sign-up trigger, the task env `TP_SESSION_SECRET`, `TP_COGNITO_BFF_KEY`,
  `TP_COGNITO_SIGNUP_PROOF_KEY`) is a follow-up: a backend + migration + Terraform change of its own.

## Should know

- A traveller who still holds the old `__Host-tp_auth` / `__Host-tp_refresh` cookies keeps them until they expire
  (30 days at most); nothing reads them.

## Follow-up (S283): the root 404 rendered into every agency page

### Decisions

- **Root cause.** The S283 live check of `/pilot-rehearsal-01/plan`, `/privacy` and `/terms` found "Adventure Asia"
  (the AA bar's home label, the "Adventure Asia AI" band, the trust strip, the footer) in the HTML although the title
  was the agency's. Next renders the root `app/not-found.tsx` into the RSC payload of every page (the not-found
  boundary of the root layout), not only when a page is missing. The import-walk guard started at the `app/[tenant]`
  files and the root layout, so it never saw AA's 404.
- **AA's 404 behind a client boundary, loaded on demand.** `app/not-found.tsx` now renders only
  `components/site/AaNotFound.tsx` ("use client") with the `preview` flag; that module loads the 404 body
  (`components/site/AaNotFoundPage.tsx`, the old content unchanged) with `next/dynamic`. Every page's payload then
  holds a client reference and `{"preview": ...}`, and the body's chunk is fetched only when the 404 is shown (checked:
  `/privacy` loads no chunk that holds the 404's text). The prerendered static 404 still has AA's bar, band and footer
  as server HTML (ssr stays on). AA's own pages and the AA-hosted demo tenant are unchanged.
- **`SiteFooter` takes `preview`.** Rendered from the client module, the footer cannot read `SITE_INDEXING` (no server
  env in the browser bundle: the server and browser renders would differ). The server page passes `!isLiveSite()`;
  every other caller leaves it out and keeps the server default.
- **The agency 404's title.** The rendered check also found `Trip planner · <agency> · Adventure Asia` on the agency
  404 (`/{slug}/no-such-page`, `/{slug}/tours/<missing>`): Next applies the root layout's template to a layout's
  `title.default` when no page sets a title. `tenantMetadata` now sets `title.absolute` (with the same agency template
  for pages), so the tab reads `Trip planner · <agency>`.
- **A rendered guard, not only a source guard.** `frontend/scripts/check-agency-render.mjs` (CI step after Build in
  "Frontend (lint + build)"): `next start` on the build against a fake browse API (localhost, one invented agency, no
  key), fetches the agency's planner, shared view, privacy, terms and two 404s on our host, and planner / privacy /
  terms on the agency's own domain (Host header), and fails when the HTML (payload included) names Adventure Asia or
  "AA AI" or lacks the agency's name. Controls: AA's `/privacy`, `/plan` and the unknown-slug 404 still say Adventure
  Asia, and the prerendered `_not-found.html` has AA's bar, band and footer as server HTML.
- **Source guard extended.** `lib/agencyBrand.test.ts` walks `app/not-found.tsx` up to its "use client" modules: that
  server part may not spell the brand, show "AA" as a word or use AA's words; the boundary must load the body with
  `next/dynamic` (no static import, no `ssr: false`).

### Should know

- A 404 under a dynamic route (`/{bogus}/plan`, `/tours/<missing>`) was already rendered in the browser by Next before
  this change (the live site answers those with the `__next_error__` shell); nothing changes there.
- `npm run build` must run before `node scripts/check-agency-render.mjs` (it serves `.next`). Local run: the same two
  commands in `frontend/` (port 3917, `RENDER_CHECK_PORT` moves it).
