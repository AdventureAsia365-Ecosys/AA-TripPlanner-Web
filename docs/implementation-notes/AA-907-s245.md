# Dependency vulnerability sweep (S245): postcss-selector-parser override

Scope extension of the pip-audit issue: close the open Dependabot alert on the frontend lockfile
(`postcss-selector-parser` < 7.1.6, GHSA-rj75-hqrm-r3gf, medium, development scope).

## Decisions

- **Top-level `overrides` entry `"postcss-selector-parser": "7.1.6"`, pinned exact.** The package comes
  in only through Tailwind 3 (`tailwindcss@3.4.14` asks `^6.0.11`, its `postcss-nested@6.2.0` asks
  `^6.1.1`). No 6.x release carries the fix and the newest Tailwind 3 (3.4.19) still asks `^6.1.2`, so a
  Tailwind bump would not help; only an override does.
- **Exact pin, not `^7.1.6`.** Matches the repo style (every direct dep is pinned exact) and keeps the
  lockfile from drifting to a later 7.x the CSS comparison below did not cover.
- **Not moving to Tailwind 4** in this PR: that is a config/CSS migration, out of scope for a
  security sweep.

## Changed

- `frontend/package.json`: one line in `overrides`. `frontend/package-lock.json`: the one
  `node_modules/postcss-selector-parser` entry 6.1.4 → 7.1.6 (`npm install`, nothing else moved).
- `CONTEXT.md`: the Frontend stack line that already explains the `overrides` block now names this one too.

## Tradeoffs

- Running 6.x consumers on 7.x. The only 7.0.0 breaking change is "make insertions during iteration
  safe"; 7.1.6 itself claims byte-identical parsing on a corpus of 8413 selectors. Checked locally: the
  Tailwind CLI output for `app/globals.css` (all content globs) is byte-identical before and after the
  override (37,684 bytes, `cmp` equal).
- Real exposure was nil (build-time parsing of our own CSS only, dev dependency), so the value is a
  clean alert list, not a reachable fix.

## Should know

- Local run on Node 22: `npm ci`, `npm run lint`, `npm run typecheck`, `npm test` (52/52 pass),
  `npm run build` all pass.
- `npm audit` still reports a `braces` advisory (GHSA-vfj7-8cjw-p6xm, `<= 3.0.3`, no fixed version
  published) under Tailwind 3's `chokidar`/`micromatch`, dev-only. GitHub has not opened a Dependabot alert
  for it on this repo; nothing to override to until `braces` ships a fix.
- Remove the override when the frontend moves to Tailwind 4 (it no longer depends on this package).
