# AA-1160 — Planner follows the agency's locale and theme; leads fall back without a CRM agency (TripPlanner part)

Linear: AA-1160 (S289). Gap evidence: root `docs/audits/2026-11-19-S285-session/aa1139/`. Other repos of the lane:
AA-CIS-App (CIS 474 `shared.tenant_crm_agency` + view columns; the CRM agency marker; the module's
`effective_channel`), AA-Partner (the module's CRM note), root (contracts tenant.entitlements.v1 1.11, tenant.addons.v1
1.2, DM-7.1 row).

## Decisions

- **Route (scope 1).** `leads.load_route` keeps CIS's `lead_channel` but sends to the CRM only while the CRM listed
  the tenant within the beacon window (`crm_pull_fresh`, unchanged 600 s). The beacon is the liveness of the tenant's
  CRM agency: the CRM lists every agency it can serve every minute (active and routed to it) and raises Forbidden /
  NotFound for a locked, offboarding or deleted one before the list call. Otherwise the agency's own route applies
  (`fallback_channel` webhook / email + target, a column CIS 474 appends: the 390 view nulls the stored target while
  crm.core is live); with no route of its own the crm channel is only unavailable now (503
  `lead_channel_unavailable`, nothing stored, as before AA-1160: the CRM may pull again).
- **Review fix pass (S289): no CIS marker in the route.** The first cut also took crm when CIS's marker
  (`crm_agency`, no expiry) was true, so a locked, offboarded or deleted CRM agency kept crm forever: new leads got
  503 (stale beacon) and the re-route counted the pending crm leads `kept_crm` until the hold expired them, the S285
  failure again. The route now reads the beacon only; CIS 474 no longer puts `crm_agency` in the view (CIS keeps the
  marker, inside an admin-editable window, for its own display). Pinned by `test_aa1038_leads_pg.py`
  `test_a_locked_crm_agency_falls_back_and_its_pending_crm_leads_move_once` and `test_aa1038_leads.py`.
- **The CRM's own call** (`serve_m2m`) uses `load_route(crm_pull=True)`: the CRM calling proves its agency, so the crm
  route holds while the add-on is live (else the first list call after a new agency would be 404 and the beacon would
  never start).
- **Re-route once** (`tp_lead_deliver` part `reroute`, before the retry): pending crm rows inside the hold whose tenant
  now resolves to webhook / email get `delivery_channel` switched in one guarded UPDATE (`WHERE delivery_channel =
  'crm' AND delivered_at IS NULL AND redacted_at IS NULL`), so a second run, or a CRM ack in between, changes nothing;
  the retry part delivers them in the same run. Recorded: the job result (`reroute`: candidates, rerouted, by_channel,
  kept_crm, no_fallback; the job row keeps it) and one `lead_rerouted` log line per lead (ids only). No tp- migration:
  the channel switch is the idempotency key and the lead list already shows the new channel and its delivery status.
- **Locale (scope 2).** The kit's typed catalogue (`ui/core/i18n.ts defineMessages`) is the app's i18n mechanism;
  `lib/planner.messages.ts` holds the planner's words, `components/PlannerLang.tsx` provides the language from the page
  (a context, so the server render already speaks the locale; `<html lang>` read at render would mismatch hydration).
  Only `/{slug}/plan` passes the agency's locale; the bare `/plan` and AA's pages stay English.
- **Theme (scope 3).** The S285 tenant set accent + accent-deep only; the kit themes only the tokens set, so tint /
  soft / border (the dashed "Start building" box) and the dark theme stayed gold, and `--tp-band-accent` (the "TRIP
  PLANNER" label) is TripPlanner's own token. `lib/tenantBrand.ts plannerBrandCss` derives the missing ones from the
  accent and checks the same contrast pairs; the agency's own tokens win.
- **Map colours (scope 3, review fix pass).** Mapbox paint reads no CSS variable, so the chosen-country fill and
  outline, the trip route, the featured legs and their labels stayed AA gold under an agency theme while the day-stop
  pins (DOM, `bg-k-accent`) took the agency colour. `plannerBrandCss` now also sets `--tp-map-fill` (the accent),
  `--tp-map-line` (the accent 16 % towards black, as AA's route is to its accent) and `--tp-map-label` (the light
  accent-deep); `MapView` reads them from `<body>` once when the map loads (`lib/mapAccent.ts mapAccentFrom`, AA's gold
  when unset or not a colour). The basemap is always the light outdoors style, so one family serves both themes and a
  theme toggle needs no repaint. `lib/mapAccent.test.ts` checks the derivation, the AA fallback and that every trip
  layer of `MapView.tsx` paints from the map accent (no gold literal left).

## Tradeoffs

- Data text stays as served: tour titles, place names, AI narration, activity kind labels (`lib/placeIcon.ts`), leg
  labels (`lib/mapbox.ts formatLeg`), the unavailable-stop reasons (`lib/availability.ts`) and the AA-only registration
  form (never on an agency planner). Follow-up if an agency asks.
- The theme derivation lives in TripPlanner, not in the kit core (a kit change needs the CIS canonical edit and a
  sync PR before this one); follow-up to move it there.
- A beacon read failure counts as "not pulled": the lead takes the fallback (delivered elsewhere, never lost), as before
  the read failure refused it.
- A CRM outage longer than the beacon window (the CRM worker down) also sends new leads, and at the daily run the
  pending crm leads, to the agency's own route: the lead reaches the agency by e-mail / webhook instead of waiting.
  Accepted (the alternative is a lead that waits or expires); the job result counts the moves (`reroute`).
