# AA-1029 R4: the tour page "from" price (S267, lane r4-price-chain)

## Decisions

- The price comes only from AA-Booking's contract view `booking.v_from_prices` (price.from.v1, Booking bk-039), read
  by the browse Lambda with the tour detail (one extra indexed read; the page is ISR-cached for 30 minutes).
- ADR 0019 d10 wants per-tenant tour reads (`catalog.v_tenant_tour_v1`); that view does not exist yet, so this is the
  AA catalogue path. The read is per catalog key, so the per-tenant path can reuse it.
- Unreadable view (bk-039 not applied, no grant) or no row: `from_price: null`, nothing shown, no error (fail soft,
  one `from_price_unreadable` log line).
- Shown as "From US$X per person" + "Suggested price for 2 travellers. Your advisor confirms the final price." in the
  "Make it yours" card and the mobile bar; JSON-LD `offers` with `priceValidUntil`.

## Changed

- The schema-boundary guard (`tests/test_extraction_ops.py`) allows `booking.v_from_prices` and nothing else of
  `booking`.

## Tradeoffs

- No per-tenant price yet: a tenant's own markup arrives with AA-1030 / the d10 views.

## Should know

- Deploy order: Booking bk-039 applied on Dev (grant) before checking the price on Dev; this code works before it
  (no price shown).

## Review follow-up (S267)

- Booking now anchors the cost sheet windows on the rate validity, so a row of an open-ended rate carries
  `valid_to = 9999-12-31` (price.from.v1: open-ended). The JSON-LD offer leaves `priceValidUntil` out for such a row
  rather than publishing year 9999.
