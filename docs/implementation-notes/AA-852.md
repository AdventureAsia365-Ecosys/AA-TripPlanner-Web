Plan: `AA-Ecosys/docs/audits/2026-10-17-S241-x1/x1-plan.md` §5 S7 (revision 2, XD8). This PR: the
migration, the TripPlanner migration lint + its CI step, the replay test, CONTEXT.md. The Infra byte copy
is a separate AA-CIS-Infra branch (`db/migrations/tripplanner/013_x1_tp_owner.sql`); it is applied in the

`shared` + SELECT/INSERT on `shared.schema_versions` for `tp_owner`). Guard 1 refuses the file otherwise.

## Decisions
- **Explicit statements, no dynamic SQL** (MIG-4, plan S6/S7): 1 schema + 15 tables + 1 view, taken from
  the schema reference of 16/10 (tp-012) and checked against tp-001…012. The two BIGSERIAL sequences
  (`trip_events_id_seq`, `outbox_id_seq`) are owned by their columns and follow `ALTER TABLE … OWNER`;
  there is no standalone sequence, function or free-standing type, so nothing else is altered. Guard 2
  ("0 objects not owned by `tp_owner`") catches anything added after the file was written.
- **Schema first.** `ALTER SCHEMA tripplanner OWNER TO tp_owner` before the tables, as in the plan: the
  next file runs as `tp_owner` and needs CREATE on the schema.
- **Default privileges:** restated `FOR ROLE tp_owner` exactly as the live `FOR ROLE aa_cis_admin` rows
  (tables SELECT/INSERT/UPDATE/DELETE, sequences USAGE/SELECT → `tripplanner`), then the old rows revoked
  in the same transaction. No function row: there was none for tripplanner (Booking has one), and new
  functions get EXECUTE to PUBLIC by default anyway. Guard 2 requires the schema's default ACL to be
  exactly the six restated entries.
- **ACL snapshot instead of trusting the ACL rewrite** (raw ACLs since review S241). Snapshot 1:
  `aclexplode()` of `pg_namespace.nspacl`, `pg_class.relacl` (NULL read as `acldefault()`, so the owner's
  own entry is compared too) and `pg_attribute.attacl` for the whole `tripplanner` namespace, every
  grantee incl. PUBLIC, grantor and grant option; the "before" copy maps `aa_cis_admin` → `tp_owner` in
  grantor and grantee; guard 2 requires exact set equality and names every lost / gained entry.
  Snapshot 2 (kept as a readable second assertion): `has_*_privilege` of `tripplanner` and `booking` on
  the schema and every relation, one privilege per call (a comma list is true when ANY is held). Views
  dropped, tables `ON COMMIT DROP`. Mutation-checked (fresh stand-in per case, PG 16): dropping one
  `ALTER TABLE`, revoking a column grant, a new column grant, a new PUBLIC grant, and an extended
  statistics / collation / text search configuration created before the transfer each raise with a
  precise message; the unchanged file applies.
- **Guard 2 scans every owned kind the DB Migrate post-check scans** (review S241): schema, relation,
  function, type, plus extended statistics, collation, operator, operator class / family, text search
  configuration / dictionary, conversion. Checked locally (PG 16): `ALTER TABLE … OWNER` does **not**
  move extended statistics (`stxowner` stays). tp-001…012 create none of these kinds, so the file has no
  `ALTER STATISTICS/COLLATION/… OWNER`; if Dev has one (out-of-band), guard 2 rolls tp-013 back instead
  of the S9 probe failing with exit 9 (pre-apply check below).
- **Guard 1 checks each 243 grant separately** (USAGE `shared`, SELECT and INSERT on
  `shared.schema_versions`): `has_table_privilege` ignores schema USAGE and a privilege list is an OR.
- **`-- migrate: lock_timeout=5s` header, no `SET LOCAL`.** DB Migrate sets lock_timeout 5s /
  statement_timeout 15min itself since N5 (same choice as tp-011/012, AA-827 notes); the header states the
  lock budget in the file. `--inspect` reports no error or warning.
- **Tests live in `migrations/tests/`, not `backend/tests/`.** A `backend/**` change redeploys both
  Lambdas on merge (`deploy-lambdas.yml` paths), and this PR ships no Lambda code (AA-827 precedent). So
  `backend/config.py:38` still says "tp-013 id-map" in a comment; fix it in the next app PR.
- **CI job "Migrations"** (review S241; replaces the offline-only step in the backend job). No layer
  may be skipped (a "skipped" line turns the job red):
  1. `migration_lint.py` (offline);
  2. `test_tp013_pg.py` on **PostgreSQL 15 + pgvector** (PGDG apt packages `postgresql-15`,
     `postgresql-15-pgvector`, own cluster on port 5433, trust auth), `--pg-major 15 --pg-require-vector`:
     the RDS Dev major (15.17) and the real `VECTOR(1536)` + HNSW index, on every PR. PG 16 changed the
     area under test (GRANT INHERIT/SET options, ALTER … OWNER and FOR ROLE checking SET, CREATEROLE), so
     the local PG 16 run alone was not proof;
  3. `test_infra_runner.py`: AA-CIS-Infra `db/run_migration.py --inspect` at the pinned commit
     `eef43c0b` (Infra main, X1 S1 #163; sparse checkout, standard library, `python -I`) on a copy of
     every file named `tripplanner/NNN_*.sql` (the runner only applies its role lint to that path shape:
     `migrations/014_x.sql` parses as dir `migrations` and skips it silently, checked), plus 8 canaries
     proving the pinned runner refuses dynamic `EXECUTE` role switches / membership grants, DEFERRABLE
     constraint triggers, `SET CONSTRAINTS … DEFERRED`, `GRANT tp_owner TO tripplanner`,
     `set_config('role', …)`, `RESET ROLE`, `SET LOCAL ROLE tp_owner` in a tp-014 file. Bump the pin when
     the Infra runner lint changes.
  Infra is private, so step 3 needs the repo secret `INFRA_READ_TOKEN` (hand step, below); missing = red.
  Service-container image `pgvector/pgvector:pg15` was the review's suggestion; the PGDG packages give the
  same major + extension with no container env vars (the official image needs a password env var).
- **TripPlanner migration lint** (`migrations/tests/migration_lint.py`, stdlib only), mirroring the
  Booking guard of X1 S5: `migration_role(n)` = `aa_cis_admin` up to tp-013, `tp_owner` from tp-014; from
  tp-013 no `SET [LOCAL] ROLE` / `RESET ROLE` / `SESSION AUTHORIZATION` / role or extension DDL /
  `SECURITY DEFINER`; every `ALTER DEFAULT PRIVILEGES` names `FOR ROLE` (from tp-014 only `tp_owner`; in
  tp-013 `aa_cis_admin` only as REVOKE); `OWNER TO` only in tp-013 and only to `tp_owner`. From tp-007:
  one BEGIN … COMMIT and the file's own `tp-NNN` registration with `ON CONFLICT (version) DO NOTHING`.
  Comments and string literals are not code (dollar-quoted bodies are). Added in review S241: every
  `ALTER DEFAULT PRIVILEGES` must name `IN SCHEMA tripplanner` (only it; without it a default grant is
  database-wide); no role membership GRANT / REVOKE (a GRANT / REVOKE without `ON`, e.g.
  `GRANT tp_owner TO tripplanner`); no `set_config('role' | 'session_authorization', …)` and no
  set_config() with a non-literal name. Dynamic SQL, deferral and the transaction shape are left to the
  Infra runner layer, which is the authority (it runs again at copy and apply time).

## Tradeoffs
- **Strict default-ACL equality** in guard 2 (exactly six entries) rather than "contains the tp_owner rows":
  an unexpected row on Dev stops the apply instead of being carried silently. Cost: a live surprise means
  a file change; acceptable (nothing changes when the guard raises).
- **No in-file behavioural probe as `tp_owner`**: the TripPlanner role lint forbids `SET LOCAL ROLE` in
  `tripplanner/`, and the master is not a member of `booking`/`tripplanner`. Behaviour is proven in the
  replay test and live after apply (plan S7 Verify) and by the S9 probe file `tp-014`.
