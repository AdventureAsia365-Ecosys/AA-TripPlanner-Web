# AA-1116 — option B in TripPlanner: AI sessions quota and the CIS stop share (slice S8)

The CIS part (migrations 435-439, contract tenant.entitlements.v1 1.9) is live on Dev. CIS 438 appends
`ai_sessions_monthly` to `catalog.v_tenant_tripplanner_v1` and `alert_pct` / `approval_pct` / `hard_stop` to
`catalog.v_tenant_ai_budget_v1`. This slice reads them. Migration tp-032 (expand).

## Decisions

- **AI session** (S282 decision 10): a `tripplanner.sessions` row with at least one AI call in a UTC month, counted once
  per month. It is counted when the session is admitted to its first AI call (after the money gates, the route and the
  per-visitor limits, right before the model call), not after the call returns: a call that then fails still used a
  place. Narration and the planning chat are counted; browse search has no session and is neither counted nor stopped.
- **Table keyed by scope, not tenant_id** (`tripplanner.ai_session_month`, tp-032): the tp-029 spelling
  `tenant:<uuid>`. A new table with a `tenant_id` column must be FORCE row-level security to stay expand (Infra
  classifier), and the tenant erasure function (tp-031) would need a contract change to delete it. The rows hold no
  personal data (a scope, a month, a random session id, a time), so they follow `ai_spend_month`: no RLS, kept as usage
  history, window before prod. No FK to `sessions` (an erased session leaves an id that points nowhere).
- **Quota at the boundary**: a session already counted this month continues past the quota (a traveller mid-trip keeps
  the AI); only NEW sessions are refused. Count and insert run in one transaction under
  `pg_advisory_xact_lock(hashtextextended('tp_ai_session_month:' || scope, 0))`, so two new sessions racing for the last
  place never both pass (pg test).
- **Fail closed for new sessions**: quota view unreadable (CIS 438 missing, no grant, any error), no row for the tenant,
  the count unreadable or the insert failing (tp-032 missing) answer `tenant_sessions_unreadable`. A counted session is
  checked first, so it continues even when the quota read fails.
- **Degrade**: a reached quota reads like a reached budget (narration basic with `ai_budget_exhausted`, the chat
  `paused` / `budget`); unreadable reads like a pause (`ai_paused`, chat `unavailable`). No new client copy.
- **Stop share from CIS** (replaces the literal 100 %): TripPlanner applies the CIS tenant budget rule
  (`shared/cost_guard.py`): hard stop on (or a 0 USD budget) = stop at `approval_pct` of the budget; hard stop off =
  alert only, as CIS's own jobs (the daily app caps of `llm_gateway.budget_status` still bound the spend). A traveller
  stage never waits for approval: it degrades at the stop share. `approval_pct` NULL fails closed.
- **Alert share**: one `tenant_ai_budget_alert` warning line per container, tenant and UTC month at `alert_pct` (no bell
  here: CIS's own budget alerts already ring for the tenant's pot).

## Changed

- `backend/shared/tenant_sessions.py` (new); `backend/assembly/ai_admission.py` (new) holds the last gates before a
  narration / chat model call (the per-visitor limits moved out of `handler.py`, then the sessions quota), so the
  handler stays inside its code-health baseline (`route` / `_chat` complexity, file length).
- `backend/shared/tenant_budget.py`: `BUDGET_SQL` reads the three 438 columns; `TenantBudget` carries them.
- `migrations/032_ai_session_month.sql` (expand) + `migrations/tests/test_tp032_pg.py`; the pg test
  `backend/tests/test_aa1116_tenant_sessions_pg.py` joins the CI "Catalog-view SQL" step list.
- `test_aa1038_leads_pg.py` budget stand-in carries the 438 columns.

## Tradeoffs

- Not done here: S282 decision 9 (the planning chat's per-tenant monthly cap derived from the tenant's TripPlanner plan AI
  increment). The increment (`ai.budget_addon_usd_monthly`) is not in any contract view TripPlanner reads; the cap stays
  the registry key `tripplanner.spend.plan_chat_tenant_monthly_cap_usd` (Platform › Settings, TripPlanner tab). Follow-up:
  CIS appends the increment to `catalog.v_tenant_tripplanner_v1` (contract 1.10), then the chat cap reads it.
- The quota read is cached 30 s per container (as the budget): a quota lowered in CIS reaches a warm Lambda within 30 s.
