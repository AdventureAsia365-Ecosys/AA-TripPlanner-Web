## Decisions

- **Token names (ADR 0016 / AA-994).** Generic scales are `--aa-*` (type, radius, space, shadow, motion,
  z-index), B2C-only surfaces are `--tp-*` (sand band, navy band, on-band text, band accent, photo
  scrims, script face, ribbon speed). All in `frontend/ui/tokens.css`; once AA-994 ships
  `ui/core/tokens.css`, the generic block moves there and is deleted here.
- **`--aa-muted` light `#656D7A` → `#5A6270`** (spec §1.1, needed: the old value is 4.48:1 on sand).
  Same value as CIS AA-760. Planner pairs re-checked by `lib/contrast.test.ts`.
- **Scrim maths (immersive graft, all three judges).** A .55 scrim gives only ~4.2:1 for white text
  over a white pixel, so:
  - `--aa-scrim` (pills and captions on photos) .55 → .68 light / .62 → .72 dark: white 6.41 / 8.48;
  - hero text sits on `--tp-scrim-text` (.70 / .74) or darker: white 6.85 / 9.17, the Satisfy kicker
    (`--tp-band-accent`, large text ≥ 28 px, 3:1 threshold) 3.74 / 4.41;
  - header text over the hero sits on `--tp-scrim-head` (.64 / .66): `--tp-on-band` 5.13 / 5.76.
  The hero layout guarantees the "text only on ≥ .70" rule: the scrim is a full-width block behind the
  text column whose gradient reaches `--tp-scrim-text` exactly where the text padding starts, and only
  gets darker below (see `components/site/HomeHero.tsx`). `lib/contrast.test.ts` composites each scrim
  over `#FFFFFF` and checks the ratio.
- **Band pairs computed** (light / dark): muted on sand 5.28 / 5.95, body on sand 10.39 / 12.19,
  accent-deep on sand 5.00 / 10.19, on-band on band 13.67 / 16.62, on-band-muted on band 9.98 / 10.55,
  band-accent on band 8.06 / 9.30.
- **Tailwind mapping without breaking the planner.** New keys only, never a redefinition of a Tailwind
  default the planner uses (`rounded-xl`, `shadow-lg`…): `text-display|h1|h3|lead|body|small|caption|kicker|script|script-sm`,
  `rounded-chip|tile|card|panel|pill`, `shadow-e1|e2|e3`, `duration-instant|fast|base|slow|reveal`,
  `ease-std|out|in`, `font-script`, `max-w-page`, `px-gutter`, `py-section`, `h-header`,
  colours `k-sand`, `k-band`, `k-on-band`, `k-on-band-muted`, `k-band-accent`, `k-band-line`, `k-band-edge`.
- **Fonts.** Poppins 400/500/600/700 + Satisfy 400 (latin, `display: "optional"`, preloaded) in the root
  layout. Fahkwang removed (`--aa-font-display` → sans). **Inter moved into `app/plan/layout.tsx`**
  (judges 1–3: do not switch the planner to Poppins in this slice; spec R10), so site pages no longer
  download it. Poppins 700 stays: the tour page and the AI label use `font-bold` (spec said drop it
  "unless a real use is found").
- **Motion gate.** `ui/restoreTheme.ts` (inline, before paint) also sets `<html data-motion="ok|reduce">`
  from `prefers-reduced-motion` (live `change` listener) and `localStorage.tp_motion === "reduce"`
  (try/catch). Every keyframe animation and every hidden "before reveal" state is scoped under
  `html[data-motion="ok"]`; under `reduce` all `--aa-dur-*` become `0.01ms`; without JS there is no
  `data-motion`, so pages are static and fully visible. A global `@media (prefers-reduced-motion:
  reduce)` net also stops animations (map-first graft). Unit-tested in `lib/restoreTheme.test.ts`.
- **Theme switch without transitions** (map-first graft): `setThemeChoice` sets
  `data-theme-switching` for two frames; CSS turns every transition off while it is set.
- **Home hero photo (spec R3: AA catalog only, ids recorded).** CIS catalog photo
  `b934482d-0889-493f-b1f0-eee36ae0a704` (China country cover, the Forbidden City at golden hour, 1080 × 1080,
  fetched from `img.lumiguides.it.com` via the public CIS photo URL). Chosen over the Bhutan Punakha cover
  (1250 × 720) because (a) the Bhutan photo is already the cover of 5 Bhutan tours on the same page, and (b) the
  square source gives a native 756 px portrait crop for 390 @2x. Built with sharp (from the CIS frontend's
  node_modules, not a TripPlanner dependency): landscape 16:9 crop (left 0, top 250, 1080 × 608) at 640/960/1080 w,
  portrait 7:10 crop (left 162, top 0, 756 × 1080) at 480/756 w, AVIF q50 effort 6 + WebP q72. Sizes: AVIF
  28–60 KB, WebP 35–81 KB (budget: ≤ 90 KB for the 390 @2x AVIF, met at 60 KB).
- **Hero copy.** Kept the existing SEO h1 "Plan your Asia adventure, tailor-made with an advisor" (immersive kept it
  too) instead of the spec's "… with someone who's been there": that claims something about every advisor we
  cannot point to (lesson S239: customer copy says only what is true). Kicker "Asia, the way few see it", lede
  (≥ 768 px only) as in the spec.
- **Header.** Navy on every customer page (solid by default, transparent on a dark scrim over the home hero).
  Below md: logo, AI chip, "Plan a trip" pill and a 44 px menu button opening a native `<dialog>` (links, account,
  theme), Esc closes it, focus returns to the button (judges 1–3). A "Skip to content" link targets `#main`, so
  every page's `<main>` got `id="main"` (one attribute on the tour, destination, sign-in, trips, legal, error and
  404 pages).
- **AI label.** New `variant="band"` (light text, white hairline) on the navy header; same label, same explanation
  popover (AA-805/819 disclosure unchanged, spec R15). Text is `--tp-on-band` (5.13:1 on the over-photo scrim),
  not on-band-muted (which would be ~3.5:1 there).
- **Search card.** "How long" = chips 5/7/10/14 plus an "Other" number field (2–30), so every length the old number
  input allowed still works; travellers = − / number / + stepper. All targets ≥ 44 px.
- **Featured tours row: no dots, no `aria-roledescription`** (judge 3's simplification): a native scroll-snap row,
  Tab moves card to card, prev / next buttons from md with `aria-controls` and `aria-disabled` at the ends. It never
  autoplays, so it has no pause control (WCAG 2.2.2 applies only to content that moves by itself; the brief's
  "pause control" is the ribbon's).
- **Ribbon pause toggle**: constant name "Pause moving photos" + `aria-pressed` (the ARIA toggle-button pattern)
  rather than a label that flips between Pause / Play (doing both confuses screen readers); the icon and the
  `title` flip. Stored per viewer in `localStorage.tp_motion_paused` (immersive graft).
- **Ribbon modes.** ≥ 8 unique photos move, 4–7 = still swipe row, < 4 = not rendered. The live home has ~7
  unique photos today (9 featured tours share 2 Bhutan / Sri Lanka covers), so production will show the still row
  until CIS has more covers (spec R2); the moving mode is covered by CSS + `lib/photos.test.ts` and can be seen
  on the preview only when the catalog has ≥ 8 distinct covers.
- **Ribbon duplicates are `aria-hidden` + `tabIndex -1`, not `inert`** (review fix). `inert` also removes a node from
  hit-testing, so copy B and the fill-rule repeats (about half of every loop) ignored clicks and hover while looking
  like the live tiles. Without `inert` they stay clickable / hoverable, are still out of the tab order (axe
  `aria-hidden-focus` passes with tabindex -1) and out of the accessibility tree. `RibbonControl`'s focus handler now
  scrolls the focused tile into view only for keyboard focus (`:focus-visible`), so a click that focuses a moving
  link (middle / ctrl click) does not scroll the clipped viewport and make the marquee jump.
- **Marquee rule uses animation longhands, never the `animation` shorthand** (review fix). The rule that starts it is
  (0,6,1) because `:not(:has(.tp-ribbon-viewport :focus-visible))` counts (0,2,0); the pause / off-screen / hover
  rules are (0,4,1). The shorthand reset `animation-play-state` to `running` with the higher specificity, so the pause
  button (WCAG 2.2.2), the off-screen pause and the hover pause never applied. Now play state is set only by the pause
  rules. Guarded by `lib/ribbonCss.test.ts` (no shorthand / no `running` on `.tp-ribbon-track`; paused rules exist;
  no `inert` in `PhotoRibbon.tsx`).
- **"Ask an advisor"** links to `/plan?ask=1`: the planner opens on the trip panel, where "Send to advisor" lives.

## Tradeoffs

- **Shared components change on pages that are not rebuilt yet.** The tour and destination pages get the navy
  header, the navy footer and the new `TourCard` now (they are shared), but keep their own layout, inline px sizes
  and the camera-icon `Photo` until slices 5–6. The header keeps its height (56 / 64 px; the tour page's sticky
  aside sits at `top-20` = 80 px, still below it).
- **Hero sharpness vs. weight.** The source is 1080 px wide, so at 1440 px the landscape crop is upscaled ~1.33×
  (spec R3). A 1920 / 2560 w variant needs a larger original in CIS (part of the "more covers" data issue).
- **`:has()` for the ribbon's keyboard still mode.** Browsers without `:has()` (Firefox < 121) drop the whole
  "animated" selector and show the still row: no motion, never a broken state.
- **Poppins 700 stays** (tour page, AI label use `font-bold`; dropping it would fake-bold them until slice 6).
- **One header for all pages.** The planner keeps its own `components/Header.tsx` (unchanged).

  chip — intended (white text was 4.2:1 on a bright photo before).
- `--aa-muted` changed on every page, the planner included (5.70 on bg, was 4.84).
- Client islands added: `HeaderScrollState` (IO), `MobileMenu` (dialog), `TourCarousel` (IO + buttons),

- Lesson candidate for the root lesson log (not written from this worktree): "a rule's `animation` shorthand resets
  `animation-play-state`; with `:not(:has(...))` in its selector it out-ranks the pause rules — start animations with
  longhands" and "`inert` kills clicks/hover, not only focus — use `aria-hidden` + `tabIndex -1` for visible
  duplicates".
- Nothing was built locally (no `next build`, no dev server, no Playwright — RAM rule of this run): `tsc --noEmit`,
  `npm test` (188 pass) and `eslint` on the touched files are clean, and the Tailwind CLI was run once to check

## S254 — one photo, one URL (browse reads)


CIS migration 290 points every copy of the same photo file (same sha256) at one canonical
`/content/photos/<id>` path in `shared.v_tour_photos` / `shared.v_destination_photos` (and so the catalog views).
`photo_id` stays each copy's own id.

## Decisions
- `backend/browse/catalog.py` dedupes photos by `path` (first occurrence in the existing order wins), via one helper
  `_unique_paths`, in both the destination page gallery and the tour detail `photos` list. Before, the gallery keyed
  on `photo_id`, which differs per copy, so one picture could show several times.

## Changed
- Tour detail also dedupes (the issue named only the gallery): a tour folder can hold two copies of the same file.
  `position` values of the kept rows are unchanged, so a dropped copy can leave a gap.

## Tradeoffs
- `photo_count` still comes from the catalog view (counts copies); only the listed photos are deduped.

## Should know
- No contract change (catalog.tour v1.2 still validates).
