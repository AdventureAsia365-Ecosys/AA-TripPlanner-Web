# AA-731 — Harness fixes before real customers

## Done in this PR
1. **Idempotent "Send to advisor"** (`assembly/handler.py`). No migration: the event log already
   is the key. One transaction, serialized per trip by `pg_advisory_xact_lock(hashtext('tp_send:'||trip_id))`.
   If the trip's latest event is already `sent` (nothing edited since) the call is a double click or
   a retry → `200 {already_sent: true, handoff_id}`, no second `sent` event, no second email, no
   second registration. Any edit after the hand-off makes the next send a new hand-off (new
   `handoff_id` = the new `sent` event id), as the issue specifies. The email is sent inside the
   transaction: a failed send rolls the `sent` event back, so the retry sends again.
2. **Atom contract** (`extraction/components.py`): atoms read from `acp_contract.v_active_tour_atoms`
   (CIS 203) instead of `tour_atoms`, inside the AA-tenant `SET LOCAL` (the view joins
   `published_tours`, which has tenant RLS). Needs CIS migration **216** (column grant on the view
   to `tripplanner`) applied first — it goes through AA-CIS-Infra DB Migrate.
3. **Orphan check**: extraction op `orphans` (read-only) counts `itinerary_components` / `tour_day`
   rows whose tour is no longer active. Run it after each rerun wave / Master trash; clean with
   `prune {"include_components": true}`.
4. **Grounded narration** (`assembly/grounding.py`): the LLM-written days are checked with the CIS
   rule (`find_novel_numeric_claims`, ADR-2026-033: a number no source text states). A "Day N:"
   line with an invented figure becomes "Day N: <component names>."; another line carrying one is
   dropped. Each day is checked against its own components; day numbers are structural. Authored
   master-content days are not checked (AA's own text). The count is logged in
   `llm_call_log.quality_signal.ungrounded_lines`.

## S235 follow-up — unverified identity claim (security)

**Finding.** `register_and_claim` reused any `tripplanner.customers` row matching the submitted
phone or email and attached the current session to it, with no proof of ownership; the outbox
payload then carried that stored customer's name/phone/consent. Anyone typing someone else's email
could attach trips to that person and send inquiries in their name. Email dedupe was case-sensitive.

### Decisions
- **Never link on an unverified match.** On a phone/email match the session stays a guest and the
  stored customer is not touched (no consent update). A new customer row is not an option: `phone`
  and `email` are `UNIQUE` (tp-001). Instead the hand-off carries a *contact snapshot* — exactly what
  this request submitted (`handoff.submitted_contact`), `customer_id: null`. It lives only in the
  outbox payload (no new column/table): that row is the durable record of the hand-off.
- **Every payload customer is flagged `verified: false`**, including first-time registrations:
  TripPlanner has no OTP. Identity + OTP move to AA-Booking later (Nghiệp's decision).
- **Email normalised to `lower(trim())`** on insert and in the snapshot; matching uses
  `lower(email) = $2` so legacy mixed-case rows still match. **No migration**: the `UNIQUE(email)`
  index stays case-sensitive, but all writes now go through the lower()-match first. A
  `lower(email)` index is unnecessary at current volume.

### Should know
- **Contract delta**: `verified` (new field) and `customer_id: null` are not valid against
  `AA-Ecosys/docs/contracts/inquiry.submitted.v1.json` (`additionalProperties: false`, `customer_id`
  required uuid). `version` stays `1`; the schema must be updated (v1.1) before AA-Booking consumes —
  no consumer exists yet.
- UX: a visitor whose contact matched an existing customer stays a guest, so a re-send after an
  edit asks for the registration form again (422 `registration_required`), and the guest session
  keeps its 90-day expiry. Acceptable until OTP exists.
