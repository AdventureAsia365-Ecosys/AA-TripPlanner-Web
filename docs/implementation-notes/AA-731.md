# AA-731 — Harness fixes before real customers

## Done in this PR
1. **Idempotent "Send to advisor"** (`assembly/handler.py`). No migration: the event log already
   is the key. One transaction, serialized per trip by `pg_advisory_xact_lock(hashtext('tp_send:'||trip_id))`.
   If the trip's latest event is already `sent` (nothing edited since) the call is a double click or
   a retry → `200 {already_sent: true, handoff_id}`, no second `sent` event, no second email, no
   second registration. Any edit after the hand-off makes the next send a new hand-off (new
   `handoff_id` = the new `sent` event id), as the issue specifies. The email is sent inside the
   transaction: a failed send rolls the `sent` event back, so the retry sends again.
2. **Atom contract** (`extraction/components.py`): atoms read from `acp_contract.v_active_tour_atoms`
   (CIS 203) instead of `tour_atoms`, inside the AA-tenant `SET LOCAL` (the view joins
   `published_tours`, which has tenant RLS). Needs CIS migration **216** (column grant on the view
   to `tripplanner`) applied first — it goes through AA-CIS-Infra DB Migrate.
3. **Orphan check**: extraction op `orphans` (read-only) counts `itinerary_components` / `tour_day`
   rows whose tour is no longer active. Run it after each rerun wave / Master trash; clean with
   `prune {"include_components": true}`.
4. **Grounded narration** (`assembly/grounding.py`): the LLM-written days are checked with the CIS
   rule (`find_novel_numeric_claims`, ADR-2026-033: a number no source text states). A "Day N:"
   line with an invented figure becomes "Day N: <component names>."; another line carrying one is
   dropped. Each day is checked against its own components; day numbers are structural. Authored
   master-content days are not checked (AA's own text). The count is logged in
   `llm_call_log.quality_signal.ungrounded_lines`.

## Not done / decisions for Nghiệp
- **Advisor email (item 5)**: already config (`ADVISOR_NOTIFY_EMAIL` env var); the default is still
  the test address and the sender is still the logging stub. Switching both is a go-live decision.
- **Automatic re-extraction after waves (item 3, automation part)**: not built. Since ADR 0002 the
  place pipeline moves to CIS (AA-712), and `components` still calls `locate.upsert` for new places,
  which the `tripplanner` role can no longer write (CIS 201). Automating it here would build on a
  frozen path; the check above is what this repo can own now.
