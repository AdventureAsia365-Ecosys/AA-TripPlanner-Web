# AA-994 — no internal issue IDs in user-visible text (rule R2)

## Decisions
- Guard `frontend/lib/noIssueIds.test.ts` (runs in `npm test`): the TypeScript compiler parses every source file of
  `app/`, `components/`, `lib/`, `ui/`, `proxy.ts`, `instrumentation.ts`; string literals, template parts and JSX text
  are checked for `\bAA-\d+\b`. Comments are not in the syntax tree, so issue IDs stay allowed there.
- One string is exempt by exact value (`NEVER_RENDERED`): the HKDF salt in `lib/seal.ts`. It is never shown, and a new
  salt would invalidate every sealed session cookie.

## Changed
- No customer or staff text carried an issue ID on main (scan and the prerendered HTML both clean); this PR adds the
  guard so it stays that way.

## Tradeoffs
- Any string literal counts, even ones never rendered. Stricter than tracing which strings reach a page; an exception
  goes into `NEVER_RENDERED` with its reason.

## Should know
- Not covered: `backend/` (Lambda) strings. The ones that name an issue are operator-only (a log note in
  `shared/llm_gateway.py`, the Sentry test event, the extraction op 410 `moved_to`), none reach a page.
