# AA-994 — no internal issue IDs in user-visible text (rule R2)

## Decisions
- Guard `frontend/lib/noIssueIds.test.ts` (runs in `npm test`): the TypeScript compiler parses every source file of
  `app/`, `components/`, `lib/`, `ui/`, `proxy.ts`, `instrumentation.ts`; string literals, template parts and JSX text
  are checked for `\bAA-\d+\b`. Comments are not in the syntax tree, so issue IDs stay allowed there.
- One string is exempt by exact value (`NEVER_RENDERED`): the HKDF salt in `lib/seal.ts`. It is never shown, and a new
  salt would invalidate every sealed session cookie.

## Changed
- No customer or staff text carried an issue ID on main (scan and the prerendered HTML both clean); this PR adds the
  guard so it stays that way.

## Tradeoffs
- Any string literal counts, even ones never rendered. Stricter than tracing which strings reach a page; an exception
  goes into `NEVER_RENDERED` with its reason.

- Review (S255): guard `backend/tests/test_no_issue_ids.py` (`ast` over the Lambda code, tests excluded; every string
  constant except docstrings), so an API error detail shown on a page cannot carry an issue ID. The three
  operator-only strings (a log note in `shared/llm_gateway.py`, the Sentry test event, the extraction op 410
  `moved_to`) are exempt by exact value in `OPERATOR_ONLY`; a third test fails when an exemption goes stale.
- Review (S255): the frontend guard also checks files served byte for byte (`public/`, non-code files under `app/`),
  comments included. `app/icon.svg` carried an issue ID in its comment; reworded.

## Should know
- The backend guard needs no AWS or DB; it runs in "Backend (pytest)".

# AA-994 S5a — TripPlanner adopts the kit core tokens (root ADR 0016, plan `docs/audits/2026-10-27-S252-aa994-design-system/plan.md` phase 5)

## Decisions
- **What was already there.** The kit-sync bot vendors the tokens profile into `frontend/ui/core/` (TP #180, #184;
  `kit.lock.json` ref `fc224ff`), but nothing imported it: the app still ran on its own copy of the palette in
  `ui/tokens.css`. S5a switches the app onto the copy.
- **Tokens.** `app/layout.tsx` imports `ui/core/tokens.css` first, then `ui/tokens.css`, which keeps only `--tp-*`
  values and the `.aa-site` base styles. Every `--aa-*` name TripPlanner reads (Tailwind config, CSS, TSX) exists in
  the core file (checked by a name diff before deleting).
- **Theme.** `ui/restoreTheme.ts` makes the one store, `createThemeStore({ storageKey: "tp_theme" })`, in a module
  without "use client", so the server layout reads `themeStore.restoreScript`; the motion gate stays a TripPlanner
  script appended after it. `ui/theme.ts` (the toggle) uses the same store and keeps two local behaviours: blocked
  storage never throws out of the toggle, and `data-theme-switching` suppresses colour transitions during a flip.
  The store also follows the theme chosen in another tab (new, from the kit).
- **Lint.** `kitConfig({ preset: "tailwind" })` on `app/`, `components/`, `ui/` (minus `ui/core`) with only rules 4, 6,
  7 on (`no-hex-colour`, `no-raw-aa-var`, `no-aa-var-definition`). The others are off: the tokens profile has no
  PageFrame / DataTable / Drawer / Modal / Button to point a page to, and there is no legacy kit here. The one
  `var(--aa-…)` string (StopActivities checkbox accent) became the Tailwind token `accent-k-accent-deep`; the rest
  (31 Mapbox paint hex values in `MapView.tsx`, which a canvas cannot read from CSS variables, and the two
  theme-color meta values in `app/layout.tsx`) are the suppressions baseline.
- **Contrast test.** The `--aa-*` pairs moved to CIS (`lib/tokensContrast.test.mjs` checks a superset of the old
  planner list on the core file). `lib/contrast.test.ts` keeps what only TripPlanner can check: the sand / navy band
  pairs and the photo scrims (they mix `--aa-*` and `--tp-*` values; read from both files, core first), the raw palette
  class ban in the planner, and a new check that `ui/tokens.css` defines no `--aa-*` value.
- **Provenance script** in `.github/scripts/` (not `backend/scripts/` as in Booking): `backend/` is what the Lambda
  packaging reads; its tests sit in `backend/tests/test_kit_provenance.py` so "Backend (pytest)" runs them.

## Changed
- `frontend/ui/tokens.css` (only `--tp-*` + base styles), `frontend/app/layout.tsx` (core import),
  `frontend/ui/restoreTheme.ts` (`themeStore`, kit restore script + motion script), `frontend/ui/theme.ts` (store),
  `frontend/lib/contrast.ts` (comments stripped before parsing: the core's comments name tokens),
  `frontend/lib/contrast.test.ts`, `frontend/lib/restoreTheme.test.ts` (+1 test), `frontend/eslint.config.mjs`,
  `frontend/eslint-suppressions.json` (new), `frontend/components/StopActivities.tsx`, comments in `tailwind.config.ts`,
  `ui/index.ts`, `app/globals.css`, `app/plan/PlannerApp.tsx`.
- `.github/workflows/ci.yml` Frontend job: integrity + `--css`, provenance, lint with `--prune-suppressions`, pruned /
  no-growth checks, no inline kit-rule disable. `.github/scripts/check_kit_provenance.py`,
  `backend/tests/test_kit_provenance.py` (from Booking).
- `CONTEXT.md` (theme and contrast section).

## Tradeoffs
- Visible value changes (the core's stricter values, plan "stale dark info/muted fixed"): light `--aa-green`
  #2E7D5B → #276B4E, `--aa-kit-amber` #B5791F → #8F5F16, `--aa-muted2` #9099A6 → #626A78; dark `--aa-info`
  #7FA0F0 → #A5BEF7, `--aa-muted` #9099A6 → #A0A8B4, `--aa-muted2` #8A93A2 → #959EAC. All darker in light / lighter
  in dark, i.e. more contrast; layout unchanged.
- `--aa-font-display` is now the kit's ("Fahkwang", Poppins, Georgia, serif). TripPlanner loads no Fahkwang, so it
  still renders Poppins; only the last-resort fallback changed (serif instead of system-ui) if Poppins fails to load.
- The lint warning that existed before (`MyTrips.tsx` location.assign) stays a warning: the job does not add
  `--max-warnings 0`.

## Should know
- Provenance runs on `pull_request` and `push` (no merge queue in this repo). It reads GitHub only when the change
  touches `frontend/kit.lock.json` or `frontend/ui/core`.
- After merge, check light and dark on production (S5b visual job, or by hand): home, `/destinations`, a destination,
  a tour, `/plan`.
