# AA-998 — Remove acc1 from the TripPlanner LLM gateway

Ecosystem decision (S255): acc1, the personal AWS account that served as the Bedrock "satellite
fallback", leaves the ecosystem. Claude runs on acc3 only; Cohere embeddings stay on acc2 first,
then acc3. The cross-account LLM fallback is given up on purpose: when acc3 fails, the route's
next model (same account) is tried, then the call fails as before (narration falls back to AA
text + neutral lines, search to keyword ranking).

## Decisions

- **Supported accounts are a closed set in code** (`llm_gateway.SUPPORTED_ACCOUNTS = ("acc3",
  "acc2")`). `_accounts()` only yields accounts from that set, so a catalog row that still carries
  an `acc1` profile (rows `sonnet`, `haiku`, `haiku-5-5`, `sonnet-5-5` until CIS migration 295
  strips it) or a stage with `account_route = 'acc1'` can never send a call to acc1, even before
  the CIS migration and the Infra apply land. The code PR alone cuts the path.
- A model whose profiles name no supported account is reported in the chain error as
  `<key>: no profile on a supported account (acc3, acc2)` instead of being silently dropped.
- `_satellite_target()` keeps one branch (acc3); any other account is `Unknown account`.
- The three `BEDROCK_*_FALLBACK` settings are deleted from `config.py` (not left as dead env).
  The Lambda env entries are removed in the matching AA-CIS-Infra PR; an env var Python no longer
  reads is harmless, so the two PRs can ship in either order.

## Changed

- `backend/config.py`: removed `BEDROCK_ACCT_FALLBACK`, `BEDROCK_ROLE_NAME_FALLBACK`,
  `BEDROCK_EXTERNAL_ID_FALLBACK` and the acc1 comments.
- `backend/shared/llm_gateway.py`: built-in `_SONNET` route acc3 only; `_accounts` order
  `(account_route, acc3, acc2)` filtered to `SUPPORTED_ACCOUNTS`; acc1 branch of
  `_satellite_target` removed; docstrings/comments.
- `backend/shared/bedrock_satellite.py`: docstring (acc3 only).
- `backend/.env.example`: fallback variables removed.
- Tests: `test_llm_gateway.py` and `test_embed_satellite_fallthrough.py` rewritten for acc3 only,
  plus guards: a stale acc1 catalog profile / `account_route='acc1'` is never called and never
  assumed; `config` has no fallback settings; no backend module (outside tests) names `acc1`.
  `test_assembly.py` failure-log test no longer uses an acc1 attempt.
- Living docs: `CONTEXT.md`, `README.md`, `.claude/CLAUDE.md`, `.kiro/steering/tech.md`,
  `.kiro/steering/structure.md`, `docs/architecture-overview.md`, `docs/e2e-uat-guide.md`,
  `docs/smoke-test-runbook.md`. The Kiro spec (`.kiro/specs/tripplanner-mvp/`) gets a historical
  note instead of a rewrite.

## Tradeoffs

- Hard filter in code vs. relying on the CIS catalog migration: the filter costs one tuple and
  removes the ordering dependency between the CIS migration, the Infra apply and this deploy.
- Historical files (`docs/implementation-notes/*`, `docs/bao-cao-hien-trang-vi.md`,
  `docs/task-assessment.md`, the MVP spec) are kept as written; they describe the past.

## Should know

- No behaviour change for a healthy acc3: today's routes already start on acc3.
- After this deploy an acc3 outage no longer retries the same model on acc1; `llm_call_log` will
  show only `acc3` / `acc2` rows for `tp_*` stages.
- Nothing in this repo needs the Infra PR to land first, and the Infra PR does not need this one.
