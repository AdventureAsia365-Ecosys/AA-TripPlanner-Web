# AA-673 — Tour Graph read model (step 2 of PR-11)

Design approved by Nghiệp in S202 (29/09/2026). Built on `tripplanner.tour_day` (AA-675).

## Decisions
- **A day's stop = its overnight destination** (`tour_day.overnight_destination_id`). A day with no
  geocoded overnight falls back to the `itinerary_components` destination with the most components
  that (tour, day), ties broken by name. `tour_stop.source` records which one was used. Only
  active published tours count (components of unpublished tours are ignored).
- **Tables** (migration 004): `tour_stop`, `tour_graph_node`, `tour_graph_edge`, `tour_leg`,
  `tour_junction`, `tour_graph_build`. Full rebuild each time, in one transaction.
- **Edge** = consecutive *known* stops of one tour (days without a stop are skipped over), A→B with
  A ≠ B. A stay (A→A) is not an edge. Weighted by the number of distinct tours taking that step.
- **Leg** = every span `[day_from, day_to]` of one tour with `day_to > day_from` whose first and last
  days both have a stop (so a leg's ends are defined for chaining). Stores the ordered distinct
  destinations, countries, and the activities of that tour's components within the span.
- **Junction at destination-pair level**, not (tour A day i, tour B day j): the pair list stays
  small, and "which legs chain here" is a query (`tour_stop` → `tour_junction` → `tour_stop`).
  Stored both directions (a, b) and (b, a) so neighbour lookups need one index. Same destination
  is implicit (km = 0, not stored). Default ≤ 150 km, a build parameter recorded in
  `tour_graph_build.params`. `cross_border` flags pairs in different countries — kept, AA-674
  decides whether to use them.
- **Computed in Python, written with plain INSERTs.** ~1.5k stops and a few hundred destinations:
  the O(n²) junction scan is ~100k haversines. Pure functions keep the rules unit-testable
  without a DB.
- **Runs in the assembly Lambda** as extraction op `tour_graph` (same path as `tour_days`, no model
  call, no cost). `invoke_tour_days.py` runs it after extracting unless `--no-graph`.

## Changed
- Added op `neighbours` (the Done-when sample query, returns its own `query_ms`) so the latency is
  measured inside the VPC, next to the DB, not through a local tunnel (there is none, AA-602).

## Tradeoffs
- Leg rows grow with the square of tour length (a 20-day tour → 190 legs); ~121 tours stay under
  ~15k rows. Accepted for simple "legs covering country X in N days" queries.
- DELETE + INSERT, not TRUNCATE: the `tripplanner` role has arwd via default privileges, not
  TRUNCATE.
