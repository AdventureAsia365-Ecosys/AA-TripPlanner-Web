# AA-990 (D1) — saved pins follow CIS component redirects (TripPlanner)

S252: 322 of 371 saved pins (99 of 103 trips) had no catalog component after the S1 v2 place re-sync in CIS. A CIS
rebuild keeps a component id only on an unambiguous one-to-one pair (AA-989); every other id is dropped. Decision D1
(Nghiệp's standing approval, S252): CIS 285 adds `geo.component_redirect`, written by the CIS rebuild for every id it
drops, served to TripPlanner as `catalog.v_component_redirect` (component_id → new_component_id, SELECT to
`tripplanner` only). TripPlanner follows it.

## Decisions

- **One place resolves ids** (`backend/shared/component_ids.py`, unchanged contract for its callers): `id_map` now
  returns where the id's chain ENDS, not one hop. At each hop the TripPlanner id map (`tripplanner.component_id_map`)
  wins over the CIS redirect of the same id (TripPlanner's own rows are the explicit decision: the AA-847 fill and
  the AA-990 backfill), then the CIS redirect.
- **Chains, ≤ 5 hops, cycle-safe** (D3): a pre-flip id → (map) catalog id → (CIS, a later rebuild dropped it) newer id →
  … The one-time AA-CIS-Infra backfill only INSERTs into the map (tp-017 keeps the map insert-only; no UPDATE grant
  needed), so its rows sit in the middle of such chains. A cycle stops at the last id before it repeats; 5 hops cover
  5 rebuilds dropping the same place, far more than a tour gets rewritten.
- **Two queries per hop**, batched over every id still moving; ids that neither source knows end after the first hop
  (2 queries where there was 1). No per-id query.
- **No TripPlanner migration**: the view is CIS's (catalog contract, granted by CIS 285); the map is unchanged.

## Changed

- `backend/tests/test_component_redirects.py` (new, offline): chain, map-and-redirect chain (map wins on the same id),

- `backend/tests/test_places_source_assembly.py`: `REDIRECT_SQL` is in the catalog-only reader allowlist.

  redirect → map chain through the event fold (CI "PG integration" job).
- `CONTEXT.md`: the id paragraph and the CIS contract row.

## Tradeoffs

- **The view must exist before this deploys** (CIS 285 applied first). The reader does not probe for it: a probe per
  call costs a query, and a failed SELECT inside a caller's transaction would abort it. The runbook order is CIS 285
  → Infra copy → DB Migrate → … → TripPlanner deploy.
- **An id is followed even when it is served again.** CIS deletes the redirect of an id a rebuild serves again (same
  transaction), so the CIS side never moves a served id. A map row (AA-847 fill, AA-990 backfill) was written for an
  id that was not served at the time; if that place comes back with the same id later the map still moves it to the
  id it named — the same place. Checking `v_tour_component` per hop would cost a query per hop for a case not seen.

## Fix round 2 (S252 review)

- **Changed:** `component_ids` reads `catalog.v_component_redirect` inside a savepoint (`conn.transaction()` when the
  connection has one, as `availability._read`). On any error it logs one `{"evt": "component_redirect_unreadable"}`
  line and the rest of that `id_map` call uses `tripplanner.component_id_map` only — so the trip fold, reorder,
  add-stops, `resolve_one` for add_day and the send-to-advisor hand-off (which holds a transaction) keep working
  before 285 is applied, after its documented rollback, or after a grant drift. This makes 285's rollback note
  ("TripPlanner falls back to tripplanner.component_id_map only") true.
- **Changed:** `events.current_custom_days` resolves every `after_component_id` through `component_ids.id_map` (one
  call for all days). Before, an extra night added after stop A kept A after a rebuild moved the pin A → … → C, so
  TripPanel (matches `after_component_id === component_id`) hid the row and its remove button while `total_days`
  still counted it, and the hand-off sent Booking the dangling id A.
- **Decision:** degrade per call, not per process: a later call retries the view (no cached "broken" flag), so the
  fallback ends by itself once 285 is applied.
- **Tests:** `test_component_redirects.py` — unreadable view → map-only result, one savepoint, one log line; add_day
  after A with redirects A → B → C → `after_component_id == C` and the folded stop id C. Local run (PyJWT added from a
  scratch dir): 159 passed over test_component_redirects / test_assembly / test_places_source_assembly /
  test_coverage / test_handoff_contract / test_trip_availability / test_tour_gone. PG tests not run (CI).
