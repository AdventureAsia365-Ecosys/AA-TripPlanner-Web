# AA-1126 — AI spend rules per environment (TripPlanner: slices G3, L2, L4)

## Decisions

- **One setting picks the rules:** `tripplanner.spend.environment` (dev | prod), seeded by CIS migration 447 in the CIS
  settings registry, edited on CIS admin Platform › Settings (TripPlanner tab, maker-checker, EN + VI guide), read here
  through `catalog.v_app_settings_v1` like every TripPlanner setting (`backend/shared/settings.py`, new kind `enum`).
  Code fallback `config.TP_SPEND_ENVIRONMENT = "dev"`, pinned equal to the CIS seed by `tests/test_s279_settings.py`.
- **dev = today's behaviour**, nothing changes on Dev until someone flips the setting.
- **prod (G3):** the app-wide caps only alert (`llm_spend_alert` threshold `cap_alert_only`): the daily cap of the app
  profile (AI gateway › App profiles) and its stage caps (`llm_gateway.budget_status`), and the planning chat's monthly
  app cap (`monthly_spend.check`). The agency's own caps stay hard: its AI budget (`tenant_budget`), its AI sessions
  quota (`tenant_sessions`, plan key `tp.ai_sessions`) and the chat's per-tenant monthly cap.
- **prod (L4):** a spend / budget / quota / count read error lets the call go on with an `llm_gateway_error` line
  (`*_degraded`). dev keeps failing closed.
- **L2 agency message:** when `tp.ai_sessions` stops a new session, one `shared.notifications` row
  `tripplanner.ai_allowance_used` per tenant and UTC month (CIS 447 grants the tripplanner role exactly that INSERT).
  The CIS Content studio bell shows it with an Upgrade link. A plain INSERT (no ON CONFLICT: the role may not SELECT the
  table, which index inference needs); the unique index's violation means "already told".
- **L2 traveller message:** neutral ("AI-written trip days are not available for this planner right now ..."), EN + VI.
  The old text said "Today's AI writing limit", wrong for a monthly quota and it named a limit the traveller cannot act
  on.

## Changed

- Review fix pass (S283): **L4 staff bell.** A degraded check under prod (`spend_unreadable`, `tenant_budget_unreadable`,
  `monthly_spend_unreadable`, `tenant_sessions`) now also raises one CIS admin bell per check and UTC day
  (`backend/shared/spend_bell.py`): event `platform.tripplanner.spend_degraded` (admin-only, AA internal tenant), plain
  INSERT, de-duplicated by the CIS 447 partial unique index `notifications_tp_spend_degraded_once_uq`; CIS 447's policy
  lets the tripplanner role write exactly that row besides the agency notice. The `llm_gateway_error` line stays.
- Review fix pass (S283): **the caps are settings.** The stage caps (`TP_DAILY_SPEND_CAP_COMPOSE_USD` /
  `_SEARCH_USD`, env-only before) and the near-cap share (`SPEND_NEAR_CAP_RATIO` 0.8) are now
  `tripplanner.spend.stage_cap_compose_usd` / `stage_cap_search_usd` (USD/day, 0 = no stage cap, the seed) and
  `tripplanner.spend.near_cap_pct` (80), seeded by CIS 447 and read through `backend/shared/settings.py`; the env vars
  are retired (never set on the Lambdas). The CIS Apps board reads the same keys instead of its mirrored constants.
  `TP_DAILY_SPEND_CAP_USD` stays the code fallback of the app profile's daily budget (its one source since CIS 414,
  AI gateway › App profiles; pinned by the CIS test `test_the_daily_cap_has_one_source_the_app_profile`), not a second
  setting.

- `tp.ai_sessions` was already enforced (AA-1116); its plan values are NULL (no limit) on both TripPlanner plans. That is
  plan data on the CIS Plans page, not code: the orchestrator sets them as a live step (S282 pricing proposal: Hosted
  300, Pro 1,500 sessions a month; the business owner may set others).

## Tradeoffs

- The degraded-check staff bell is written through the database that may be the reason the check failed: best effort,
  paced per container (one attempt per check and UTC day, a failed write retries after 60 s), never raises. A database
  outage therefore still shows only as the ERROR lines until it recovers; any partial failure (one view, one grant)
  reaches the admin bell.

- The notice attempt is paced per container (one per tenant and month, a failed write retries after the tenant budget's
  failure TTL), so a busy agency at its quota does not write on every refused session.
