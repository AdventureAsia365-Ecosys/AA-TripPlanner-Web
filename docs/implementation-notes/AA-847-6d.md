## Decisions
- **Tiles carry no geometry** (bbox intersection on the never-null `min/max_lat/lng` of `catalog.v_destination`, CIS
  256); the geometry comes from `GET /browse/shapes?ids=&level=lo|mid` (≤ 50 ids, sorted + deduped = one CDN key per
  set; `lo` below zoom 7). Supersedes the 6c notes' "shape travels with the destination row" (a long river would ship
  in every tile it crosses; GROUP BY jsonb).
- **6c hardening**: `isExactPin` — only `point` (or a legacy row with no precision) is an exact pin; `area`, `line` or
  any value a newer CIS adds is never one (planner map: the area style; static maps: the grey pin, or a path).
- **Line style**: class from the name (`lib/lines.ts lineClass`: water / road / trail; the last linear word wins), not
  from OSM tags (the views do not expose them). Dashes are two layers with filters (`line-dasharray` is not
  data-driven in GL JS 2). Trails dashed, approximate routes dashed and labelled "approximate route".
- **Browse map, line without geometry** (pending / not_found / failed): not drawn on the browse map (no anchors there);
  it stays in lists and is flagged on CIS `/admin/places` "Lines". The trip map always draws something: the stretch,
  or the provisional dashed line between the day's two stops.
- **Trip legs** (`planTrip` → `fetchTripLegs`): a line day whose stretch runs from stop A to stop B replaces the A→B
  leg (mode `feature`, no Directions request); joins A→start / end→B are requested only when > 2 km (JOIN_KM). A window
  around one stop (out-and-back) is drawn as an extra stretch and replaces nothing. Net Directions requests: same or
  fewer (unit test). TripPanel uses the same plan (its connector map is keyed by the leg's departure stop).
- **Static maps**: `staticMapUrl` moved to `lib/staticMap.ts` (pure, tested); lines are `path-4+<color>-0.85(<encoded
  polyline>)` overlays, ≤ 3 lines × 60 vertices; when the URL would reach 8,192 characters the last paths are dropped
  (pins and the route stay). The tour page draws the day stretch (else the line's `shape_lo`), the country page the
  `shape_lo`; numbered lists skip lines (〰 glyph instead of a number).
- **Contracts**: the tour answer is `catalog.tour` v1.2 (version field now 1.2; places carry `segment*` and
  `shape_lo` for line places); vendored copy `backend/tests/contracts/catalog.tour.v1.2.json` (byte copy of root,
  sha256 49c922bb…). The assembly components gain the five `segment*` fields (catalog.graph v1.2).
- **Kill switch** `NEXT_PUBLIC_MAP_LINES_PROVISIONAL` (on: every line drawn in the provisional dashed ink style).

## Tradeoffs
- One more request per view with lines (`/browse/shapes`, ≤ 50 ids, cached client-side and on the CDN) instead of
  shipping geometry in tiles: tiles stay small and cacheable; a river is fetched once per level.
- Line class from the name instead of OSM tags: a "Song X" / "Nam X" river without the English word reads as water
  through the region words; a misclassified line only changes its colour, never its position.
