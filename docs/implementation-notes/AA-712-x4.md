# AA-712 X4 — TripPlanner reads CIS only through the catalog views (lane aa712-zero, S248)

Branch `feat/aa712-tp-cis-only`. The $0 leftovers of AA-847 (Done S247, `PLACES_SOURCE=cis` live since 22/10/2026):
remove the legacy place readers, so that CIS 270 can revoke the remaining `tripplanner` grants on CIS objects and
tp-018 can drop the frozen place tables. Written while implementing.

## Decisions

- **Remove the switch, not just flip its default.** `PLACES_SOURCE`, `backend/shared/places_source.py` and every
  `*_SQL` legacy constant are gone; the former `*_SQL_CIS` constants take the plain names (`events.COMPONENTS_SQL`,
  `routes.SINGLE_SQL`, `suggestions.ROUTE_CANDIDATES_SQL`, …). A default flip would have left dead SQL naming tables
  tp-018 drops and grants CIS 270 revokes.
- **What TripPlanner may still read is a whitelist, enforced by a test.** `test_extraction_ops.py`
  (`test_no_backend_module_reads_cis_internals_or_the_frozen_place_tables`) parses every backend module, takes the
  non-docstring string literals and fails on any schema-qualified object outside `catalog.*`, the Model Gateway
  (`shared.llm_role_config`, `shared.llm_model_catalog`, `shared.llm_call_log`) and the live `tripplanner` tables.
  This is the evidence CIS 270 relies on.
- **The Model Gateway grants stay (CIS 173).** TripPlanner's own LLM calls read the route config and write
  `llm_call_log`; that is a standing contract, not a content read.
- **`component_id_map` stays and is always read.** It no longer depends on the flag: drafts from before the flip
  keep their old ids in `trip_events` for ever, so the map outlives `itinerary_components`.
- **Extraction checks removed.** `list` / `orphans` / `neighbours` read only the frozen tables; they now answer 410
  like the former writer ops (`extraction/checks.py` deleted). `catalog_rls.py` (tenant GUC for `published_tours`)
  and `config.MASTER_CONTENT_TENANT_ID` / `SCHEMA_GOLD` / `SCHEMA_ACP` went with the last caller.
- **`x-places-source` header removed** (no consumer outside the parity probe and tests).
- **`tour_route(conn, tour_id)` lost its `also` ids.** The legacy graph was keyed by whichever tour_id it was
  extracted under; the catalog graph is keyed by `source_id`, which survives re-uploads.

## Tradeoffs

- **No rollback to `legacy` once this ships.** Accepted: AA-847 closed with the post-flip burst (1,367 calls, all 200)
  and X4 drops the tables anyway. Rolling back this PR alone (before tp-018) still works: the grants are revoked only
  by CIS 270, applied after this deploy.
- `test_route_property_pg.py`: the rewrite changed the seeded draw and found a pre-existing cross-tour gap
  (seed 674 set 0: pins on two tours joined at a junction; the route suggestion continues one tour and the trip
  re-sequences into a 551 km gap). The suggestion property is now checked for single-tour sets only, with the
  counter-example in the test. Product follow-up belongs to AA-674 (suggest inside the covering chain), not here.
- `test_vector_topk_pg.py` needs pgvector; it was not run locally (no pgvector on this machine) and CI does not run
  it either (no `--pg-dsn` in the backend job). `test_places_source_pg.py` + `test_route_property_pg.py` ran on a
  local PostgreSQL 16 (16 passed).

  "Backend (pytest)" job skipped them. They now run in the existing "Migrations (lint, PG 15 replay)" job on its

  no-skip grep and a PASSED line required per module. Local run of that exact command on PostgreSQL 15.19 +
  pgvector 0.8.7: 24 passed (15 + 1 + 8), the pgvector top-k search included.

## tp-018 (branch `feat/aa712-tp018-drop-frozen`, stacked on the reader removal) — NEEDS APPROVAL AFTER THE DRY RUN

- **One file, eight tables, RESTRICT.** `DROP TABLE IF EXISTS` of `itinerary_components`, `tour_day`, `tour_stop`,
  `tour_graph_build`, `tour_graph_edge`, `tour_graph_node`, `tour_leg`, `tour_junction` in one statement (inter-table
  order does not matter). No CASCADE: an unexpected dependent stops the apply instead of disappearing with it.
- **Guards before the drop** (RAISE, nothing changes): run as `tp_owner`; no view / rule / foreign key outside the
  eight depends on them (listed); no row written on or after 2026-10-16 00:00 UTC in the three tables with a write
  time (`itinerary_components.created_at`, `tour_day.extracted_at`, `tour_graph_build.built_at`): slice 6a removed
  the writers on 14/10, one day of margin. If the DRY RUN shows a later write, stop and find the writer; do not move
  the cutoff without that.
- **`-- migrate: destructive`**: DB Migrate takes the manual RDS snapshot first and refuses to apply without it
  (MIG-12). That snapshot is the only undo.
- **Kept:** `tripplanner.component_id_map` (no FK to the dropped table; old draft ids keep resolving).
- **Replay-twice test:** tp-003, tp-004 and tp-013 can no longer re-run on the final state (they create / re-own
  the dropped tables); they are listed in `SUPERSEDED_BY_DROP` with the reason, and a probe checks each still fails
  or changes the state (so the list cannot go stale). tp-013's own re-run stays covered by `test_tp013_pg.py`.
- Local run: `pytest migrations/tests --pg-dsn … --pg-major 16` on PostgreSQL 16 without pgvector: 55 passed
  (CI runs PostgreSQL 15 + pgvector).
