# AA-993 — delivery pipeline (TripPlanner)

## CI speed (slice 6), PR-1: TP-1 — 26/10/2026

Source: root repo `docs/audits/2026-10-26-S252-aa993-delivery-pipeline/ci-speed-plan.md` §2 (TripPlanner rows) and
§4 row 4. File: `backend/tests/test_vector_topk_pg.py` (test code only; no workflow change).

### Decisions

- **TP-1:** a sync, module-scoped `template_db` fixture (built with `asyncio.run`) creates `tp_aa712_tpl_<uuid>`,
  applies `SCHEMA`, runs `_load` (which ends with `ANALYZE`) and closes every connection. The function-scoped `db`
  fixture is now `CREATE DATABASE "<name>" TEMPLATE "<tpl>"` plus one connection; each test still gets its own
  database and drops it. The template is dropped in a `finally` at module teardown (also when the build fails).
- The fixture `ctx` (topics, queries, rng) is built once and shared; the tests only read `ctx["queries"]`. The query
  vectors are the same as before (seeded `random.Random(712)`); component ids were `uuid4` per build before and are
  now fixed for the module, which no test depends on.
- **No xdist:** it would break the `PASSED` grep guard in the `Catalog-view SQL` step. The guard and the step are
  unchanged.

### Changed (vs. the plan)

- Module docstring updated to describe the template. A small `_db_dsn()` helper builds the per-database DSN for both
  fixtures. Commit subject `ci:` (orchestrator's instruction).

### Tradeoffs

- One HNSW graph per module instead of one per test. The graph was already non-deterministic per run (random
  component ids), so the approximate-search test sees the same class of input.

### Should know

- Postgres refuses to copy a template with open sessions; the build closes its connection before the first copy, and
  `CREATE DATABASE` waits up to 5 s for an exiting backend.
- Local checks: `pytest tests/test_vector_topk_pg.py` without `--pg-dsn` collects all 8 tests and skips them (no
  pgvector on this machine, no throwaway cluster), so the real run is CI's `Catalog-view SQL` step. The sync
  `asyncio.run` module fixture + async function fixture pattern was checked separately under pytest 9.0.3 +
  pytest-asyncio 1.4.0 (`asyncio_mode = auto`, function loop scope): built once, all async tests pass.
- Re-measure (plan §4 row 4): `Catalog-view SQL` step 61 s → about 33 s; wall 1.62 → about 1.27 min (dev PRs 1.55 →
  about 1.2); all tests PASSED and the grep guard holds.
