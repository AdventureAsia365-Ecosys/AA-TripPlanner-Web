# AA-642 S8 — TripPlanner on the shared AI gateway core (root ADR 0009 decision 13)

The canonical notes are in AA-CIS-App `docs/implementation-notes/AA-642-s8.md`; this file covers the TripPlanner
side only.

## Decisions

- **Vendored core.** `backend/aa_llm/` is a byte copy of AA-CIS-App `shared/aa_llm/` with `backend/aa_llm.lock.json`
  (CIS commit, manifest sha256). `package_lambdas.sh` already ships all of `backend/`, so the Lambda zips carry it
  with no build change; `backend/scripts/` is dropped from the zip.
- **Reads.** `load_route` reads `catalog.v_llm_gateway_config_v1` (one row per chain model, `position` order, keys not
  in the catalog skipped as before). `_spent` reads `catalog.v_llm_app_spend_today_v1`. Only SQLSTATE 42P01 / 42501
  (view missing or not granted: CIS 323 not applied yet) falls back to the old source (the two `shared.*` tables /
  `tripplanner.llm_spend_daily`); the view is then not tried again for `VIEW_RETRY_SECONDS` (300 s, per container).
  Any other error keeps the AA-642 S0 fail-closed path (AI paused).
- **Ledger v2.** `record()` writes `aa_llm.ledger.LedgerRow` (35 columns): `app = 'tripplanner'`, `status` (`ok`, or
  `refused` / `error` from `aa_llm.ledger.failed_outcome`, the CIS client's rule), `error_class`, `latency_ms`,
  `attempt_no` (1-based per request), `connection_key` = the account key (`acc2` / `acc3`), `deployment_wire_id` =
  the Bedrock profile called, cache tokens, `pricing_mode = 'catalog'` for a priced success. On SQLSTATE 42703 (no
  v2 columns) it writes the pre-319 row. `quality_signal` keeps `app`, the error and `failed` (CIS readers and the
  pre-v2 rows of the spend view use them).
- **Spend decision.** `budget_status` builds its answer with `aa_llm.budget.decide` / `unreadable` (same dict).

## Changed

- A failed ledger write of an online stage now also starts the spend-unreadable hold: the spend view sums the
  ledger, so a lost row would undercount like a lost counter write.
- `tripplanner.llm_spend_daily` is still written (fallback source until 323 is applied; nothing else changes).

## Tradeoffs

- Deployments in the view are not used yet (TripPlanner still calls the catalog profile per account); they are in the
  contract so a later slice can move to deployment-based dispatch without a new view.

## Should know

- Never edit `backend/aa_llm/`. After a CIS change: the Llm Core Sync bot opens `bot/llm-core-sync` here, or run
  `tools/llm-core/llm-core-sync.sh tripplanner` from the root workspace.
- `python3 backend/scripts/check_vendored_copies.py` (network) also checks the lock commit is on CIS main and that
  `shared/identity_verifier.py` equals CIS main; `--offline` is what `tests/test_vendored_copies.py` runs.
