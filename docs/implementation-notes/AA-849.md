# AA-849 — TripPlanner migration replay CI: twice, registry keys, no skips

Split from AA-807 (S239). TP #96 already added the CI job "Migrations (lint, PG 15 replay)" (lint + tp-013 /
tp-015 replays on PostgreSQL 15 + pgvector, red on a "skipped" summary). This change adds what the Linear
comment of 19/10 lists as still open: replay twice, assert the registered keys, red evidence, required check.

## Decisions
- **One new test module, `migrations/tests/test_replay_twice_pg.py`, in the existing job.** No new job: the
  job already has the PG 15 + pgvector cluster and the "no skipped tests" gate, and adding a module keeps
  the required-check name unchanged ("Migrations (lint, PG 15 replay)").
- **Pass 1 = every `migrations/NNN_*.sql`, in file order, as DB Migrate would run it.** The role is the
  runner's XD8 rule (the live owner of schema `tripplanner`, read before each file; the login role while it
  owns the schema or the schema does not exist yet), and the test asserts that this equals
  `migration_lint.migration_role(n)` for every file. 002 before 001 (tp-001's FK), the CIS 243 grants right
  before tp-013 (as on Dev). It reuses the stand-in of `test_tp013_pg.py` (roles, master `aa_cis_admin`
  NOSUPERUSER, `shared.schema_versions`, live default privileges).
- **Pass 2 = every file again, each as the role it ran as in pass 1, and it must change nothing.** "No
  error" alone is not idempotency: the test snapshots the catalog of schemas `tripplanner` and `shared`
  (owners, ACLs incl. columns, default ACLs, columns + defaults, constraints, indexes, view and function
  definitions, triggers, comments), the row count of every table there and every `shared.schema_versions`
  row with its `applied_at`, before and after pass 2, and requires equality (a file that registers with
  `DO UPDATE`, duplicates a seed row or re-grants differently goes red with the diff in the message).
- **Pass 2 uses the pass-1 role, not the runner's live-owner rule.** After tp-013 the runner would pick
  `tp_owner` for every file, and tp-001/002/005/013 cannot run as `tp_owner` (CREATE on the database /
  schema `shared`, owner of `shared.destinations`, default privileges FOR ROLE aa_cis_admin). DB Migrate
  never re-runs them anyway (registered → `apply` skips). Re-running as the original role answers the
  question that matters: is the file safe to run again in the context it was written for.
- **tp-001 is the one exemption** (`NOT_RERUNNABLE`, frozen): pre-convention (plain `CREATE TABLE`), registered
  only by tp-007's backfill, so DB Migrate never re-runs it; making it idempotent means editing an applied
  file and its AA-CIS-Infra byte copy. Pass 2 asserts it is registered instead, and a test proves the
  exemption is still needed (re-running it still raises `DuplicateTableError`) and that it only covers files
  before the registry convention (tp-007), so no new file can hide there.
- **Registry = files.** After pass 1 (and again after pass 2) the set of `tp-%` keys in
  `shared.schema_versions` must equal `{tp-NNN}` of the files: a file that forgets to register, registers
  another number, or a stray key all fail.
- **Runtime grants as a standing check:** after both passes every table of `tripplanner` grants
  SELECT/INSERT/UPDATE/DELETE to `tripplanner` and every sequence USAGE + SELECT (what the `FOR ROLE
  tp_owner` default privileges of tp-013 give). Honest scope: in the stand-in the default privileges exist
  before tp-001, so this mostly guards against a later file revoking runtime rights; the exact owner / ACL
  / default-privilege assertions stay in `test_tp013_pg.py` / `test_tp015_pg.py`. A table that must deny
  the runtime something needs an explicit exception in the test.
- **Mutation-checked locally** (PG 16, `real[]` stand-in; temporary `016_mut.sql`, removed): a plain
  `CREATE TABLE` → pass-2 error test red; an unguarded seed `INSERT` → "pass 2 changes nothing" red with
  the `rows` diff; no registration → both registry tests red; `REVOKE UPDATE … FROM tripplanner` → grants
  test red; a file that errors → every test errors with `pass 1: 016_mut.sql as tp_owner: …`. A file with
  `IF NOT EXISTS` + `COMMENT ON`, and a `CREATE OR REPLACE VIEW`, stay green. (A registration with
  `DO UPDATE` cannot even pass pass 1 from tp-014 on: `tp_owner` has only SELECT, INSERT on
  `shared.schema_versions`, CIS 243.)

## Changed
- vs. the issue scope: no `postgres:15` service container and no `shared.llm_call_log` stub. TP #96 already
  chose a PGDG PostgreSQL 15 + pgvector cluster in the job (AA-852 notes), and no file touches
  `shared.llm_call_log` (tp-010 / tp-015 only name it in comments); `shared.destinations` comes from
  tp-002 itself, the roles and `shared.schema_versions` from the tp-013 test's stand-in.
- CI step: besides "N skipped", the step now also fails on xfailed / xpassed / deselected and on a run
  that collected no replay test (the replay modules must report PASSED lines). A `--fail-on-skip`
  conftest option turns any skip into a non-zero exit inside pytest too, so the gate does not rely only on
  grepping the summary line.

## Tradeoffs
- The second pass runs the file text again; it does not emulate the runner's "skip when registered"
  (that would make pass 2 a no-op by construction). The runner's skip is covered by the registry check.
- Local runs on PostgreSQL 16 without pgvector use the `real[]` stand-in of `test_tp013_pg.py`; CI pins
  15 + pgvector.
