# AA-805 — TripPlanner AI Phase 0 + leg-order fix (S236)

Lane tp-805, branch `fix/aa-805-ai-phase0-leg-order`. Written while implementing.

## Decisions

- **Leg order — root cause is the projection, not only the algorithm.** `apply-route` pins the
  route's components and then appends a `reorder` event with the route's day order. The next
  event (`sent`) made `_latest_explicit_order()` return `None`, because it only looked at the very
  last event; the hand-off itinerary was therefore re-sequenced by geography (west-most first),
  which produced the S235 legs `3–4, 7, 2, 1`. Fix: a manual order now stays valid until the
  component *set* changes (`add_component` / `remove_component`); `sent`, `add_day`, `remove_day`
  no longer drop it.
- **Sequencing keeps a tour's day order.** Without a manual order, components from the same source
  tour form one block ordered by `source_day_index` (then id). Nearest-neighbour now orders
  *blocks* (enter at a block's first day, leave at its last), not single pins. A component with no
  source tour is a block of one, so the old behaviour holds for free pins.
- **Narration ownership = `trip_drafts.session_id`** (the session that created the trip; the
  upsert never changes it). Strict equality — a different session gets 403, even for the same
  registered customer, because customer links are not verified (no OTP, S235).
- **Narration cache in `tripplanner.narration_cache`** (new migration `010_ai_phase0.sql`, key
  `tp-010`): key = sha256 over mode + prompt version + each day's (day, component_id, name,
  text_extract, source_tour_id, source_day_index). Cross-trip by design: the text comes only from
  catalog content, no user data. Only narrations that used the LLM are cached; pure master text
  is cheap and must follow CIS edits at once. TTL `NARRATION_CACHE_TTL_HOURS` (default 168).
- **Spend hard stop.** The forked gateway had no budget mechanism, and the `tripplanner` role only
  has INSERT on `shared.llm_call_log` (no SELECT). Rather than ask CIS for SELECT on every app's
  call log, the gateway keeps its own counter `tripplanner.llm_spend_daily` (UTC day x stage),
  incremented by `record()`. Cap: `TP_DAILY_SPEND_CAP_USD`, default **5.0 USD/day across the
  customer-facing stages** (`ONLINE_STAGES` = `tp_compose`, `tp_search_embed`) — a placeholder,
  see open questions. (Review fix: originally every tp_* stage counted.)
- **Budget exhausted behaviour.** Narration: days without AA master text get a neutral
  `Day N: <component names>.` line (same shape grounding uses), response carries
  `ai_budget_exhausted: true`, nothing is cached. Search: 503 `search_unavailable`.
- **Failed calls are logged.** Each failed attempt (per model x account) becomes a
  `shared.llm_call_log` row with `stop_reason = 'error'`, tokens 0, `cost_usd` 0 and
  `quality_signal.failed = true` + the error text. Bedrock does not bill a rejected request.
- **Unknown price is NULL, not 0.** Catalog prices are `Optional`; a call whose needed price is
  missing logs `cost_usd = NULL` and prints a warning. NULL cost is not added to the daily spend
  counter; the counter's `unpriced_calls` column counts them.
- **Shadow config is documented, not honoured.** `shadow_model_id` / `shadow_sample_pct` are read;
  if a tp_* stage has a shadow configured the gateway prints a warning and runs only the primary.
  Honouring it would double the spend and needs an INSERT grant on `shared.llm_shadow_log`.
- **Contract version.** `docs/contracts/inquiry.submitted.v1.1.json` declares `version` as the
  number `1.1` (enum `[1, 1.1]`), so the payload carries `1.1` as a number, not the string "1.1".
  `tripplanner.outbox.schema_version` is an integer column and stays the major (1).
- **Search.** Query embedding uses `input_type = "search_query"` (Cohere asymmetric search;
  components were embedded as `search_document`). Results only include components whose source
  tour is `published_tours.master_status = 'active'`; the query runs tenant-scoped (RLS) like
  `fetch_catalog`.
- **Frontend.** "AI-assisted" pill right after the AA logo (visible on mobile, unlike the wordmark
  block); "AI narration" badge when the narration is LLM-only; "AA + AI" stays for mixed. Badges
  key off `source` (the new `basic` source shows none). The API also returns `ai_generated` and
  `cached` for other clients; the frontend does not need them yet.
- **Fallback source `basic`.** Over the cap the narration can still contain master lines, but it is
  labelled `basic` (not `master`) so nobody reads the neutral day lines as AA-authored text.

## Tradeoffs

- Block sequencing keeps a whole tour together even if the traveller pinned stops far apart in
  the same tour; that matches how AA sells the tour and the hand-off legs. A user who wants a
  different order can still drag (manual order wins).
- Budget counter in our own schema vs. reading `shared.llm_call_log`: no cross-app grant needed,
  but the counter can drift from the log if a write fails (both are best-effort; the log stays the
  billing source of truth).
- Spend/cache tables missing (migration not yet applied): both fail **open** with a printed
  warning, so a deploy before tp-010 does not break narration or search. Apply tp-010 first.

## Review fixes (S236 review round 1)

- **Spend cap scope (major).** Only `ONLINE_STAGES` (`tp_compose`, `tp_search_embed`) are added
  to `llm_spend_daily` and summed by `budget_status()` (`AND stage = ANY($1)`). Offline
  `tp_extract` / `tp_component_embed` are still logged in `shared.llm_call_log` but no longer
  count, so an extraction or embedding backfill cannot make search 503 / narration 'basic' for the
  rest of the UTC day. Offline spend has no cap of its own here — backfills are run by hand and
  already bounded by the paid-run rules. Test: `test_offline_stages_never_exhaust_the_customer_budget`.
- **Cache key includes master text (minor).** `/narrate` now loads the AA master day texts before
  the cache lookup (`_load_master_texts`) and passes them to `itinerary_hash()`; each entry's
  authored text is part of the key, so a CIS edit misses the cache. Chosen over "cache only LLM
  lines and re-merge" because it keeps the cache a single stored string and costs one read the
  narration needed anyway (`_narrate` reuses the loaded map).
- **Basic narration colon (minor).** A nameless day is now `Day N: free day.` so `_merge_by_day`
  keeps it.
- **Active filter (minor).** Added `pt.deleted_at IS NULL`. Kept `pt.tour_id::text =
  c.source_tour_id`: `source_tour_id` is `text` and a `::uuid` cast on it would raise for any
  non-uuid value; the table is ~886 rows.
- **Contract guard (minor).** `jsonschema==4.23.0` added to the dev/test block of
  `requirements.txt` (the Lambda packager installs only the runtime block).

## S237 — live evidence round (branch `chore/aa-805-evidence`)

Full evidence: root workspace `docs/audits/2026-10-14-S237-lane-backlog/aa805-evidence.md`.

### Decisions

- **Evidence over HTTP only.** The sub-agent was limited to curl against the prod alias BFF plus
  read-only AWS describe calls: no Lambda invoke, no DB, no AWS writes. Booking was read through its
  staff API with the CIS E2E admin. Lines that need the DB (spend rows, cache summary, inactive-tour
  join) are listed for the orchestrator instead of being guessed.
- **Labelled set shape.** `/browse/search` returns destinations, not tours, so the label per query is
  "expected countries + minimum top-5 hits" (relevance) and the inactive-tour rule is a DB join on the
  returned destination ids. Single labeller (Claude Code), not a panel. This is said in the fixture.
- **No public "cache stats" endpoint** (lane plan): the browse/trip APIs only carry the edge key, so
  the README documents the SQL surface instead.

### Changed

- `backend/tests/fixtures/search_labelled_30.json` (new), `backend/tests/test_search_labelled_set.py`
  (new, offline shape guard), README section "Reading the AI guards (AA-805)". No runtime code.

### Tradeoffs

- The relevance threshold per query is a judgement call (4/5 for named places, 3/5 for activities).
  24/30 passed live. The 6 misses are catalog coverage (Chitwan, Ladakh, Fuji, Thailand thin), and
  relevance is not part of the Done-when.
