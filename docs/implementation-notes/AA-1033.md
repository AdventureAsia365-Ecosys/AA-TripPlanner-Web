# AA-1033 — AI-output notice (TripPlanner: traveller notice + terms "Use of AI")

Lane ai-notice, S263. Kit side: AA-CIS-App `docs/implementation-notes/AA-1033.md`.

## Decisions

- **Sentence from the kit, look from TripPlanner.** ADR 0016 decision 2 keeps TripPlanner's B2C components here and
  gives it only the kit `tokens` profile. The CIS PR adds `aiNotice.messages.ts` (and `i18n.ts`, its one import) to
  that profile, so `ui/AiNotice.tsx` renders the exact ecosystem sentence from `ui/core/` without a local copy (a test
  fails if the sentence is typed into the component). Styling is TripPlanner Tailwind tokens: `page` (muted) and
  `band` (navy footer) tones, `md` / `sm` sizes.
- **Placements:** tour page — at the end of the "Day by day" section (under the AI-written summary, highlights and
  days; the existing AA-819 labels stay); planner — under the narration blocks in `TripPanel`; footer — every site page,
  with a "Use of AI" link to `/terms#ai` (`TERMS_AI_PATH`, lib/legal.ts).
- **Planner (review fix pass):** `/plan` renders no `SiteFooter`, so the footer line never shows there. Every planner
  surface with CIS writer-model text carries the notice itself, with a "Use of AI" link (new tab, keeps the trip):
  the map popup (`DestinationPopup`, under the experience list, outside its scroll area, only when a description
  shows), the stop activity list (`StopActivities`, next to its AI label; one stop's list is open at a time) and the
  narration (`TripPanel`). `ui/AiNotice` gained an optional `termsHref` prop for the link; `ui/` stays free of
  `@/lib` imports, callers pass `TERMS_AI_PATH`.
- **Terms §3** renamed "AI-assisted content" → "Use of AI" (id `ai` kept, so links stay valid) and extended: what AI
  writes (tour text, narration, search and suggestions — same facts as `AI_SITE_EXPLANATION`, AA-819 verified), that
  it can make mistakes, that it is for information, and that the confirmed quote and booking conditions bind. No
  liability waiver; §7 Liability stays "[to be confirmed]" for counsel.
- English only: TripPlanner pages are English (the VI table in `lib/aiNotices.ts` is only for planner status notices).

## Changed

- Nothing beyond the issue. No backend change.

## Tradeoffs

- Footer line on every page vs only on tour pages: the issue asked for both; the footer line is small (caption size)
  and sits in the bottom row with the copyright, so it does not compete with page content.
