# TL-24 — the Dev and preview sites are not indexed and say they are a preview (S262)

Decision: root `docs/audits/2026-10-31-S262-tl-decisions/README.md` (TL-24 approved: noindex and a "preview" line until
go-live; the business owner gets one line about the lost SEO value of the Dev host). Source: the S261 architecture
review §7.2. No Linear issue of its own; the PR refs the review's tracking issue.

## Decisions

- **Explicit flag, preview by default.** `SITE_INDEXING=on` in the Vercel env marks the live site; anything else, or
  nothing, is a preview. `VERCEL_ENV` cannot decide: the Dev host `aa-tripplanner.vercel.app` is a Vercel production
  deployment. Default-preview means a forgotten flag hides the site from search instead of exposing a test site.
- **Three signals.** Root layout `robots: { index: false, follow: false }`; `X-Robots-Tag: noindex, nofollow` on every
  response from `next.config.mjs` (covers API JSON, images and the 410 page too); `robots.txt` keeps its crawl rules but
  drops the sitemap line. No site-wide `Disallow`: a blocked crawler never sees the noindex, and URLs it already knows
  stay listed.
- **Pages that set their own `robots`** replace the layout's value; every one of them sets `index: false` today, so
  they stay out of search either way. The header covers anything a page forgets.
- **Footer only for the line.** `SiteFooter` (server component) shows the note on the kit pages. The `/plan` planner has
  no footer and its layout fills the viewport; adding a banner there would move the planner, and the lane may touch only
  layout, metadata and robots files besides. `/plan` is noindex already (page metadata) and gets the header too.
- **English only.** The site has no Vietnamese UI (pages default to English); the line is English like the rest.
- **One rule in two files.** `next.config.mjs` cannot import TypeScript, so `previewHeaders()` repeats the
  `isLiveSite()` rule; `lib/siteMode.test.ts` imports both and checks they agree.

## Changed

- New `frontend/lib/siteMode.ts` (+ test). `app/robots.ts`, `app/layout.tsx`, `next.config.mjs`,
  `components/site/SiteFooter.tsx`, `CONTEXT.md` (SEO section).

## Tradeoffs

- The env is read when Next loads the config and renders static pages (build time on Vercel): changing the flag needs
  a redeploy, which go-live does anyway.
- The visual workflow's screenshots change (one more footer line); it is report-only.

## Should know

- At go-live: set `SITE_INDEXING` to `on` in the live Vercel project's Production env (by script, not by hand-copying
  the name), redeploy, check `robots.txt` lists the sitemap and the responses carry no `X-Robots-Tag`.
- Until then, Google may keep pages it indexed earlier for a while; the noindex removes them on the next crawl.
