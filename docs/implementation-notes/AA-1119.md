# AA-1119 — Release safety (AA-TripPlanner-Web part)

Whole picture, decisions and merge order: root `docs/implementation-notes/AA-1119.md` (S291, lane e-release-safety;
S282 audit R31, R32, R40).

## Decisions

- **Merge queue ready**: `ci.yml` and `pr-title.yml` run on `merge_group`; the code-health, suppression and kit
  provenance steps read `github.event.merge_group.base_sha` there. `secret-scan.yml` takes AA-Booking's guard (accepts a
  `merge_group` trigger, scans the group's commits) without the trigger itself: the trigger lands in a second PR,
  because the `gitleaks` job runs the base branch's copy and the old guard refuses a second trigger. The second PR adds
  the trigger and empties `PENDING_TRIGGER` in `test_merge_queue_ruleset.py`.
- **Ruleset**: `.github/rulesets/main-merge-queue.json` (same parameters as AA-Booking's) + the strict PATCH, applied
  by the tech lead once PR B is merged (`.github/rulesets/README.md`). `test_merge_queue_ruleset.py` lists the required
  checks and their workflows.
- **Coverage floor**: `backend/.coveragerc` `fail_under = 90.0` (measured 90.31 % on 24/11/2026: 1747 passed, 99
  PostgreSQL tests skipped offline); `.github/scripts/coverage_floor.py check --base` refuses a lower floor than the
  base's. `pytest-cov==7.0.0` sits in the dev block of `backend/requirements.txt`, which `package_lambdas.sh` never
  packages. The frontend has no coverage floor yet (follow-up).
- **Rollback after a red post-deploy check** (`deploy-web-dev.yml`): the deploy job records the revision the service runs before
  `update-service` (`ecs_smoke_rollback.py previous`); when `verify` or `release` fails on main after a successful deploy, job
  `rollback` moves the service back to it (`ecs_smoke_rollback.py rollback --apply`), refusing and changing nothing when
  the target is unknown or unsafe; job `report` opens or comments on the `deploy-smoke-red` issue and closes it on the
  next verified deploy. `result` is unchanged: the run stays red.
- `.github/scripts/ecs_smoke_rollback.py` and its test are byte copies of the same files in AA-CIS-App, AA-Booking,
  AA-Partner and AA-TripPlanner-Web: change them in all four in one wave.

## Tradeoffs

- A flaky post-deploy check now rolls back a good build; the next deploy of main brings it back and the issue records
  it. Accepted by the audit (R32).

## Should know

- The rollback job uses the deploy job's OIDC role and only calls it already makes (describe, ECR describe-images,
  update-service, wait); no IAM change.
