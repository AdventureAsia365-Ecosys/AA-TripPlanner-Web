# AA-856 — Search under load: query-embedding cache + keyword fallback (S239)

TripPlanner half of AA-856, branch `fix/aa856-search-embed-cache`. Companion changes:

- AA-CIS-App `feat/aa856-cohere-global-profile`: migration 238 switches the `cohere-embed-v4` acc2
  profile in `shared.llm_model_catalog` from `us.cohere.embed-v4:0` to `global.cohere.embed-v4:0`.
- AA-CIS-Infra `chore/aa856-copy`: byte copy of that migration for DB Migrate.
- AA-CIS-Infra `fix/aa856-tp-embed-global-iam`: the browse/assembly Lambda role may invoke the
  `global.` profile (it allows only `us.` today). **Apply before migration 238**, or every
  TripPlanner search embed gets AccessDenied (with this branch: keyword fallback for everyone).

## Decisions

- **Cache in the Lambda container only** (`llm_gateway.EmbeddingCache`, bounded LRU 1024 entries,
  TTL 6 h, vectors stored as `array('d')`, about 12 KB each, so at most about 12 MB). No shared cache
  table / Redis: there is no Redis, and a table would need a tp migration plus a DB round trip per
  search for a gain only across containers. The S239 burst repeats one query (`q=hanoi`), so each
  container embeds once. Revisit if CloudWatch shows a low hit rate with many containers.
- **Key** = stage + model keys of the route + input type + embedding dimension + normalised text
  (NFKC, case-folded, whitespace collapsed). A model change on the admin Settings page gives new
  keys, so a vector never crosses models. The TTL only bounds staleness.
- **The normalised text is what gets embedded**, so one key always maps to the same vector,
  whoever asked first. Case-folding a query changes Cohere vectors only marginally.
- **A cache hit is not a model call**: no `shared.llm_call_log` row and nothing added to
  `tripplanner.llm_spend_daily` (issue scope 4: "cache hits not billed"). A hit is served even when
  the daily cap is reached, because it spends nothing. A miss over the cap is still 503 (AA-805).
- **Fallback on any `BedrockError` from the embed** (throttle, AccessDenied, malformed reply...):
  200 with a keyword ranking and `"ranking": "keyword"`; the semantic answer now carries
  `"ranking": "semantic"` (additive field, the BFF passes the body through, the frontend reads
  `destinations` only). Failed attempts are still logged as failed `llm_call_log` rows.
- **Keyword ranking without pg_trgm**: the shared RDS has only `vector` and `pg_stat_statements`
  (db-schema-reference.md, Extensions), and installing an extension is CIS/Infra territory. So
  each query word (letters/digits, 2+ chars, small stopword list, at most 8 words) becomes an
  `ILIKE '%word%'` pattern, scored per component: destination name 3, component name 2, country or
  component text 1, summed over the words; best component per destination, ties by the number of
  filtered components. Same `BrowseFilters.where_sql` filters, same active-tour rule (legacy path,
  run with the AA tenant set) or live-tour views (cis path). Words are `[^\W_]+`, so no LIKE
  wildcard or escape can come from the user; patterns are bound as one `text[]` parameter.
- **Throttle cooldown 10 s per container**: after a throttle the container ranks by keyword without
  trying Bedrock (the 20 rpm bucket refills one request every 3 s; trying again at once spends it).
  Other errors do not start a cooldown.
- **acc2 embed client with no retry** (`_acc2_embed_client`, `max_attempts=1`, one client per
  container), as CIS did in AA-610: the default boto3 client retried a throttle up to 4 times with
  backoff, holding the request for seconds and spending the same minute's quota again. Only for
  the default client factory; tests inject their own.
- **Log line**: one `{"evt": "search_embed", "outcome": "hit"|"miss"|"fallback", "reason"?,
  "cache_hits", "cache_misses", "cache_size"}` per search (print, like `guest_auth`), never the
  query text. Hit rate = hits / (hits + misses) per container, or count outcomes in Logs Insights.
- **Built-in route keeps `us.cohere.embed-v4:0`**: it is used only when the gateway tables cannot
  be read, and the Lambda role keeps the `us.` grant, so it works before and after migration 238.

## Changed

- Issue scope 1 asked for "in-Lambda LRU + a shared cache table or Redis if available": only the
  in-Lambda LRU is built (see Decisions).
- Issue scope 3 (quota): requested by Nghiệp in S239 on the **global** cross-region quota
  `L-7089DC7D` (adjustable), case 179212369200770, 20 -> 2,500 rpm, status CASE_OPENED (read
  16/10/2026). The `us.` quota `L-EB8C1F30` is not adjustable, hence the profile switch (CIS
  migration 238 + Infra IAM).

## Tradeoffs

- Substring matching is crude (`an` matches "lantern"); it is a degraded mode for a throttle, not a
  ranking to keep. Accent-insensitive matching would need `unaccent`.
- Keyword ranking scans all filtered components (about 4k rows legacy; the cis path already does a
  full aggregate over `catalog.v_tour_component` for semantic search, so no worse).
- A per-container cache means N cold containers embed the same query N times; acceptable at
  2,500 rpm, and the fallback covers the gap at 20 rpm.
