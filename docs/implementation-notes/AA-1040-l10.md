# AA-1040 (lane l10) — the AI mark in the browse Lambda's catalog JSON (AA-TripPlanner-Web)

S266, EU AI Act Art. 50(2), root ADR 0019 d19. The root AI Use Register listed "the browse Lambda JSON" as a surface
with a visible label and page attributes but no machine mark in the data itself.

## Decisions

- `backend/browse/catalog.py` `catalog_ai_mark(generated_at, published_at)` adds `ai` to every tour card (`_card`:
  list, home, destination pages) and to the tour detail. Same object and generator name as the CIS tour reads
  (tenant pool, catalog.http.v1 1.3 `Tour.ai`): `ai_generated` true, `generator` "Adventure Asia catalog writer",
  `model` null and `human_edited` null (both recorded admin-side in CIS, not in the catalog views), `generated_at` =
  `text_updated_at` (last Master publish of the text), else `published_at`.
- **`generated_at` is the text time (review fix).** `v_tour.updated_at` is GREATEST(published_at,
  master_updated_at, photos_updated_at) (CIS 273 / 289): a photo change moved it, so the mark reported a later
  generation time than the CIS tenant reads. CIS 359 appends `text_updated_at` = COALESCE(master_updated_at,
  published_at) to `catalog.v_tour`; the card and detail reads select it and the mark uses it, else `updated_at`.
- **Either order with CIS 359.** `has_text_updated_at(pool)` asks `pg_attribute` whether the column exists; a true
  answer is kept for the Lambda's lifetime, a false one is asked again on the next request (one catalog lookup).
  Before 359 the `TOUR_CARDS_SQL_PRE_359` / `TOUR_BY_SLUG_SQL_PRE_359` reads select `NULL AS text_updated_at`, so
  the Lambda never fails on the missing column and the mark falls back to `updated_at` (an upper bound).
- The Lambda reads `catalog.v_tour`, whose text is all Master text, and derives the mark from its columns. `ai` is a Lambda helper next to the `catalog.tour` view fields (like `cover_url`), so
  the vendored `catalog.tour.v1.2.json` is unchanged and `_contract_view` in the test drops it.
- Frontend: `CatalogAiMark` type (optional on `TourCard` / `TourDetail`, an older Lambda answer has none) and
  `tourTextMark(tour)`, which prefers `ai.generated_at` for the page's `data-ai-generated-at`.

## Changed

- `backend/browse/catalog.py`, `backend/tests/test_browse_ai_mark.py`, `backend/tests/test_catalog.py` (helper).
- `frontend/lib/catalogTypes.ts`, `frontend/lib/aiNotices.ts`, `frontend/app/tours/[slug]/page.tsx`,
  `frontend/lib/aiNoticeKit.test.ts`, `CONTEXT.md`.

## Tradeoffs

- The cards carry the mark too (a few bytes each): their title, subtitle, summary and highlights are the same AI text.

## Should know

- The exact `generated_at` needs CIS 359 applied on Dev; before that the JSON shows `updated_at` (an upper bound).
- Deploy is the Lambda deploy (`deploy-lambdas.yml`) plus Vercel for the page change; the JSON is CDN-cached with the
  browse TTL, so the live check may need one cache cycle.
