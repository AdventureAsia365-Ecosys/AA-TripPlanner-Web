## Decisions

- **Dark mode = the planner follows the site theme** (proposed by the orchestrator, act now; Nghiệp
  can overrule). TripPlanner already has a light/dark/system toggle on every kit page (AA-812), and
  `/plan` was the one page pinned to light (`pinLightTheme` + a `/plan` branch in the restore
  script). Moving the planner onto the theme tokens makes dark work for free, so the pin is removed
  and the planner header gets the same `ThemeToggle`. The alternative — keep `/plan` light-only and
  only fix light contrast — would have left the one inconsistent page and made "axe in dark" a
  tautology.
- **The Mapbox basemap stays light (`outdoors-v12`) in both themes.** The map is imagery on a canvas
  (axe does not read it; pins/route colours were designed against it). A dark basemap
  (`dark-v11`) would need every overlay layer colour re-tuned and a style swap on theme change —
  a design task, not a contrast fix. Dark chrome around a light map is a common pattern.
- **One palette.** All planner classes moved from the Tailwind `aa.*` hex palette to the kit `k-*`
  tokens, and the `aa.*` colour palette is deleted from `tailwind.config.ts` (the `shadow-aa*`
  shadows stay). Mapping: `aa-ink`→`k-ink`, `aa-ink-soft`→`k-body`, `aa-muted`→`k-muted`,
  `aa-line`→`k-line`, `aa-offwhite`→`k-bg`, `aa-sand`→`k-neutral-bg` (muted on it 4.74 / 4.62),
  `aa-sand/50`→`k-bg`, `white`→`k-card`, `aa-gold-soft`→`k-accent-tint`, `aa-gold-dark` and
  `aa-gold` text→`k-accent-deep`, gold borders→`k-accent-border` (soft) / `k-accent` (solid),
  red→`k-danger*` (new Tailwind key `danger-border`). Text on solid fills: gold fill →
  `bg-k-accent text-k-on-accent` (7.42 / 8.9, the kit primary button), ink fill (inverted pills) →
  `bg-k-ink text-k-bg` (13.67 / 15.87). Hover `bg-aa-gold-dark` → `hover:brightness-95` (kit Button).
- **No token value changed.** The AA-812 tokens already pass in both themes for every pair the
  planner uses; the violations came only from the old hex palette.
- **D11 is fixed in the BFF, not the Lambda.** A 4xx on a browser `fetch` is always printed as a red
  network error, whatever the JS does, so the browser must not get a 404 for an expected answer.
  `/api/browse` turns the tour-route 404 into `200 { match: "none", tour }` (no-store)
  (`lib/tourRoute.ts`); the client reads `match: "none"` (and still a legacy 404) as "missing". The
  Lambda keeps its REST-correct 404 and its tests, and nothing needs a Lambda deploy.
- **Also fixed: the first-visit trip read 404.** The prod baseline showed a second red console error
  on `/plan`: `GET /api/trip?trip_id=…` → 404 for a trip that has no draft yet (AA-909: refused and
  unknown reads are the same 404). It fires on every first visit, Customise included, so the
  Done-when "console shows no error" could not hold without it. The `/api/trip` BFF now sends the
  **itinerary** read's 404 as `200 { itinerary: [], custom_days: [] }` (`tripReadAnswer`), which is
  what the client already did with a 404. The body is the same for "no such trip" and "not your
  trip", so existence still never leaks. Suggestions / coverage / activities reads pass through.
- **Day labels:** `formatDays(n)` ("1 day" / "N days", "0 days") and `formatDayRange(min, max, sep)`
  (equal ends collapse: "1 day") in `lib/text.ts`; `daysText` uses `formatDays`. Applied at every
  day-count label: TourListPane (card + confirm), PlanPrefill (confirm + fallback), RoutePlanner
  (proposals + "no route of about N days"), TripPanel (badge + long-trip warning), HomeSearch chips,
  home country cards, destination intro.

## Tradeoffs

- Token unit test vs. axe in CI: the repo has no Playwright/axe dependency or UI smoke workflow, and
  adding one (browser download in CI, a running app with mock Lambdas) is larger than this issue.
  The unit test guards the two things that broke here (token values, raw classes) at zero CI cost;
  the rendered-page axe run is a script used locally and on the preview (below). Issue scope item 4
  ("optional: axe in the UI smoke") is therefore not wired into CI — TripPlanner has no UI smoke job.
- `opacity-60` on the dragged trip card and `disabled:opacity-50` stay: transient/disabled states
  that axe and WCAG exclude.
- The guard scans only the planner's files (`components/*.tsx`, `app/plan/PlannerApp.tsx`); kit
  pages use `text-white` over photo scrims on purpose.
