# AA-1137 T8 — TripPlanner's orphan spec moves to the archive (S285 lane l20-hooks-specs-apps)

Task T8 of the root spec `.kiro/specs/AA-1137-spec-trace/` (requirement R5.2: only issue specs stay under
`.kiro/specs/`; a spec without an issue moves to `.kiro/specs/_archive/`).

## Decisions

- **Moved, not rewritten.** `.kiro/specs/tripplanner-mvp/` (the v0.3 MVP spec, no front-matter, no issue) moves to
  `.kiro/specs/_archive/tripplanner-mvp/` unchanged (`git mv`), so its history follows it. The three live pages that
  name it (README, `docs/task-assessment.md`, `docs/bao-cao-hien-trang-vi.md`) point at the new path; implementation
  notes keep the path they had when they were written.
- **A separate PR from the Spec trace caller, merged first.** The trace checker checks every spec a PR changes, and
  the archived folder has no front-matter: in the caller's PR (or after it) this move would turn Spec trace red.
  Without the caller on `main`, this PR runs no Spec trace.
- **A short `.kiro/specs/README.md`** says where issue specs go, what `_archive/` holds and which check reads them.

## Changed

- `.kiro/specs/tripplanner-mvp/` -> `.kiro/specs/_archive/tripplanner-mvp/`; new `.kiro/specs/README.md`; three path
  references updated.

## Tradeoffs

- The archived spec stays in Kiro's old free format; giving it front-matter would invent an issue it never had.

## Should know

- Once the caller is on `main`, a later PR that edits a file under `_archive/tripplanner-mvp/` gets a red Spec trace
  (no front-matter). Leave the folder as it is.
