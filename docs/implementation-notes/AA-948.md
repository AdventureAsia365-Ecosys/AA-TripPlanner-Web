# AA-948: a shared map engine extracted from the planner map (AA-TripPlanner-Web part)

Tech lead decision S294 D8: the CRM proposal builder (AA-Partner) uses the same map engine as the planner, a
framework-free package extracted from `components/MapView.tsx`, instead of forking the TripPlanner map. This repo holds
the canonical copy; AA-Partner holds a byte copy checked against it.

## Decisions

- **Where shared code lives**: the UI kit's pattern (root ADR 0016): one canonical folder in the repo the code came
  from, byte copies elsewhere, each copy pinned by a lock file and checked by integrity + provenance in the consumer's
  CI. No npm package (GitHub Free, public repos, `turbopack.root` makes `file:` dependencies unworkable: the same
  reasons as ADR 0016).
- **Canonical folder** `frontend/lib/map-engine/` (not under `ui/`, which holds the kit copy; `lib/` is outside the
  kit lint, so the engine's neutral defaults are not page colours). Files: `geo.ts`, `motion.ts`, `layers.ts`,
  `engine.ts`, `index.ts` (framework-free entry), `react.ts` (the React binding entry), `check-map-engine.mjs` (the
  guards, dependency-free) and `MANIFEST.json`.
- **Framework-free core**: no React or Next import outside `react.ts`; mapbox-gl is passed in to `createMapEngine`
  (a type import only, plus `loadMapboxGl()`'s dynamic import), so the engine runs in node tests with a fake module.
- **Relative imports stay extensionless** (`./geo`): every consumer's bundler resolves them; the node test loads a temp
  copy with `.ts` added (the kit core's `aiNotice` test does the same).
- **What moved into the engine** from MapView: map creation (token, style, camera), the sizing fixes (two animation
  frames, ResizeObserver, resize on load), Mapbox error reporting, teardown, camera framing (`fitTo`, `easeTo`) under the
  site's reduce-motion gate (AA-995), DOM markers by key (the trip stop markers), layer clicks with the pointer cursor
  (the pin / area / line hit layers), great-circle legs, and the route preview's "stops + route" layer set
  (`addRouteLayers`, `routeStops`, `routeCollection`). **What stays in MapView**: every planner layer and its paint
  (accent colours, clusters, lines), the tile loader, the trip legs, gateways, popups of destinations (a React
  component), and all planner state.
- **No visible change**: the same style, camera, layer ids and paint values; only one hex literal fewer in MapView (the
  route preview's white stop ring is the engine's default), so `eslint-suppressions.json` shrinks by one.

## Changed

- `components/MapView.tsx` uses the engine; `lib/mapReady.test.ts` looks for `engine.destroy()` / `.fitTo(` instead of
  `map.remove()` / `map.fitBounds(` (the same guarantees: ready inside the load handler, reset on removal, the country
  effect frames the pins).
- New: `lib/map-engine/` and `lib/mapEngine.test.ts` (geometry, motion, engine with a fake mapbox-gl, layers, the core's
  import rules, MapView drawing through the engine, the integrity / sync / import guard script).

## Tradeoffs

- The consumer import guard ships with the core (like the kit's `check-kit-copy.mjs`), so a consumer runs the same
  rule its copy was checked with. A relative import may reach the rest of the consumer's own repository (its e2e
  helpers), never a folder outside it.
- `fitTo` computes plain min/max bounds, as `LngLatBounds.extend` did; neither handles the antimeridian (no AA region
  crosses it).
