# AA-1025 slice H1b (S265 lane l1-h1bc): TripPlanner acts on its app profile

Plan: root `docs/audits/2026-11-01-S263-gateway-gap-audit/plan.md` row H1 (H1a = the CIS table and admin, CIS 345 /
346 and AA-CIS-App #1263; this slice = TripPlanner). Root ADR 0009 decisions 4 (app profile) and 13 (contract views).
$0: no provider call.

## Decisions

- **Read through a CIS contract view, not the table.** The `tripplanner` role reads the CIS control plane only through
  `catalog.v_llm_*` views (decision 13). CIS migration 347 adds `catalog.v_llm_app_profile_v1`: the `tripplanner` row
  of `shared.llm_app_profile`, six columns (not the admin's free-text reason, not `updated_by`), SELECT to
  `tripplanner` only.
- **Fail open, the CIS rule.** No row, the view missing / not granted (before 347) or any read error = AI on and no
  profile budget. Cached 20 s (the CIS gateway's TTL); a missing view is retried after 300 s, another error after
  60 s (one `llm_gateway_error` line, `what: app_profile_unreadable`). The spend cap itself still fails closed. A
  database that cannot be read also stops the route and spend reads, so failing open here does not open spend.
- **The AI switch sits in `load_route`.** Every model call of TripPlanner starts with `load_route` (narration through
  `_resolve_narrator`, search in `_query_vector`), so one check covers both and a new caller cannot skip it. AI off:
  one 0 USD ledger row (status `refused`, error_class `disabled`, no connection, `quality_signal.not_called = ai_off`)
  and `AiPaused("ai_off")`. The row's error text names the stage the way the CIS stage kill switch does
  (`stage '<stage>' is switched off by an admin`), so the core's `failed_outcome` classifies it `disabled` too.
- **Degrade = the existing paused path** (degrade mode `basic_narration`, tech lead T-21): narration answers
  basic / master_basic with `ai_paused` and one `narration_degraded` line (reason `ai_off`); search the keyword
  ranking with `ai_paused` (`ai_off` added to `PAUSED_REASONS`). The planner already shows its calm "AI paused" line.
- **The narration limit is counted after the route is resolved** (was before). A request that AI-off or an
  unreadable route refuses never calls a model, so it is not counted (the AA-1015 rule "only requests that would call
  a model are counted").
- **The cap from the profile replaces the env cap when set.** `default_daily_budget_usd` set = the daily cap over
  every `tp_*` stage (the whole app's ledger spend today through `catalog.v_llm_app_spend_today_v1`, offline stages
  included: "a cap for offline stages"), alert scope `app`, `cap_source: app_profile`. Not set = the AA-805 behaviour:
  `TP_DAILY_SPEND_CAP_USD` over the online stages. Both caps at once was rejected: an admin raising the budget in CIS
  would still be stopped by a Lambda env value they cannot see. The stage caps (AA-1015) apply either way.
- **The spend alert reaches CIS through the ledger, not the log line.** The CIS ops check `llm_spend_alert`
  (AA-CIS-App, same lane) reads the same profile row and the same ledger rows and writes the admin bell and the ops
  e-mail. No CloudWatch metric filter (paid) and no new write path from TripPlanner into `shared`.

## Changed

  (the fake databases answer any SQL).
- Docs: `CONTEXT.md`, `README.md`.

## Tradeoffs

- One extra `fetchrow` per container every 20 s (a one-row view). Cheaper than a model call by far.
- A switch reaches a warm container within 20 s, not at once (the same as CIS's other tasks).
- The whole-app spend has no fallback. Rebased onto AA-1027 E5 (TP #215): the tp-010 counter
  `tripplanner.llm_spend_daily` is neither written nor read (tp-025 drops it), so `_spent(db, None)` reads only
  `catalog.v_llm_app_spend_today_v1` summed over every stage (`_APP_SPEND_ALL_SQL`, the same view as
  `contract.APP_SPEND_SQL` with no stage filter; `backend/aa_llm` is a pinned CIS copy, so the SQL lives in the
  gateway). A view that is missing, not granted or failing = `spend_unreadable` (fail closed), like the per-stage
  read. Only the profile read itself fails open.
