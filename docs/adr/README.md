# AA-TripPlanner-Web ADRs

No app-level ADR yet. Decisions that shape this app today are ecosystem ADRs in the private AA-Ecosys repo
under `docs/adr/` (for example 0001 target architecture, 0002 only CIS writes content, 0004b per-app security
groups, 0006 identity, 0008 new-app integration and data platform rules). Infrastructure-only decisions live in
AA-CIS-Infra.

Write an ADR here when a decision is hard to reverse and, if reversed, would change this repo only (for example
the map provider, the trip state model or the session and guest-token design). A decision that would also change
another repo goes to the root ADRs instead; an app ADR that implements one cites it.

Each ADR is `docs/adr/NNNN-<slug>.md`, numbered from `0001`, with a status line near the top
(`- **Status:** Accepted (dd/mm/yyyy, S<nnn>)`). Add it to this table in the same PR.
